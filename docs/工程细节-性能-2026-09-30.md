## 1. 帧缓存（预缩放）——"点一下设置冻 3 秒"的根修

**症状**（2026-09-29 用户报「打开/选择设置时卡顿」）：点一次「想法气泡」**冻 3192ms**。

**根因**：`_recreate_window()`（气泡/大小/布局变更都走它）原来**无条件**重建帧缓存 ——
重新解码 525 帧 PNG 再逐帧 GDI+ 重采样。拆解实测：

| 环节 | 耗时 |
|---|---|
| `Surface()` 创建 | 0.04 ms/帧 |
| `clear()` | 0.07 ms/帧 |
| **`DrawImage` 缩放（HighQuality 插值）** | **3.9 ms/帧** ← 全部时间在这 |
| PNG 解码 | 0.88 ms/帧 |
| 合计 525 帧 | ≈ 3.2 s |

**改法（三个旋钮）**：
1. **构建依据签名** `_cache_sig()` = `(sc, pet_h, ok_glyph_h)` —— 帧缓存**只跟显示尺寸有关**，
   而 `_layout()` 里 `pet_h` 与气泡开关无关 → **气泡开关不再重建**（3.2s → 3ms）。
2. **改尺寸走后台**：`_build_cache_objects()`（纯函数、不碰 self）→ daemon 线程 →
   `_wait_cache_new()`（挂 `_anim_tick`）原子换引用；UI **18.5ms** 返回。
   过渡期用旧缓存**拉伸顶住** —— 为此 `_draw_anim_frame` 里"尺寸差 >16% 就跳过绘制"那条保护
   必须对 `_cache_building` 放行，否则缩放跳档时她**整帧不画 = 消失**。
   首次（启动）仍同步建，否则首帧没素材。
3. 重建期间**同时存在两份缓存**（旧 + 新 ≈ 130MB×2 瞬时），`_apply_cache()` 换上时关掉旧的。

⚠️ **别顺手降插值等级**：Bilinear 比 HighQuality 快 2.3x，但实测两者**alpha 合成结果不同**
（同一帧像素均差 3.36/255，颜色深浅肉眼可辨）→ 会改变观感，收益不值。

## 2. 菜单（自绘分层窗口）

**耗时画像**（`tools/_prof_menu.py`，还没做的话先跑它，别猜）：

| 环节 | 修前 | 修后 |
|---|---|---|
| ① 弹出前构建条目 | 11.3 ms | **0.7 ms** |
| ② 建窗 + 首绘 + ULW 上屏 | 7.5 ms | 7~10 ms |
| ③ 整卡重绘（15 条目） | 3.5 ms | 3.5~4.4 ms（单条 0.10ms） |
| ④ 悬停切换一次 | 4~5 ms | 4~5 ms |
| ⑤ 子菜单展开+收起 | 11~12 ms | 同（改的是**何时**开，不是多快） |
| ⑦ 点「想法气泡」 | **3192 ms** | **3 ms** |
| ⑦ 点「桌宠大小」 | **3192 ms** | **18.5 ms**（后台建 3.15s） |

三个来源与修法：
- **条目构建每次都查库**（`stale_working_sessions` ~10.9ms）→ `_stale_list_cached(20s)` TTL。
- **帧缓存重建**（见上）→ 签名 + 后台。
- **子菜单一 hover 就展开**（建窗+渲染 12ms/次，鼠标扫过菜单时一路闪）→
  **停留 `SUB_OPEN_DELAY_S=0.14` 才开**：`on_move` 只记 `_sub_pending=(idx,t0)`，
  靠菜单窗口的 `WM_TIMER`（`ID_TIMER_SUB`，60ms 一跳）在 `on_timer()` 里展开；
  `_teardown` 必须 `KillTimer`。实例字段 `_fall_debounce_s`/`_sub_timer_on` 供测试观察。

## 3. 跟随模式（前台切换 agent）

**症状**（2026-09-30 用户报「切换不同 agent 时卡顿」）：**切一次冻 10.3 秒**。

**根因**：`wb_follow.handoff_last_turn` 直查**视图** `v_turn_total`（多层 VIEW + 每行 `json_extract`，
基础表 1GB+，视图无法建索引）→ 实测 **10304 ms**；而它是在**每次确认切换**时同步调用的。
连切 5 次 = 45912 ms。

**改法**：走 `wb_hover_core.turn_src()`（优先物化表 `dws_turn`，同查询 **12.7ms**）
+ `_HANDOFF_CACHE` **5s TTL**（窗口语义本来就是"2 分钟内算未结束"，5 秒陈值够用）。
同一处坑的另一个漏网：`wb_whale_win._handoff_expand`（右键「生成接续摘要」，点一次冻十秒）→ 一并改。

修后逐段实测（`tools/_prof_follow.py`）：`_fg_window_info` 0.12ms ｜ hint+resolve 0.01ms ｜
**`_follow_commit` 5.4ms**（含接续检测）｜ 连切 5 次 39.9ms（TTL 命中 15.6ms）｜
`_follow_tick` 稳态 0.08ms/帧 ｜ 切换后那一帧 draw 3.7ms。

## 4. 「她还动吗」怎么量（像素哈希算帧率）

`_pet_fps.py`（工作目录）：每 150ms 用 `PrintWindow(hwnd, memdc, 2)` 抓桌宠窗口，
对像素算 md5，统计"每秒变化次数"与"两次变化之间的最长间隔"。

- **正常值：约 24.4~24.8 帧/秒，最长无变化间隔 < 0.1s**（41ms/帧）；
- **最长间隔 > 1.5s = 她冻住了**（用来抓"静默冻结"类问题，比盯着看客观）。

## 5. 取数本身的成本（别让它上 UI 线程）

- `wb_hover_core.query_db`（`tick` 每秒一次）：实测 **22ms** —— 可接受，但别再往上加；
- 任何"轮次/会话"聚合：**必须**走 `turn_src()`（见 §3）；
- 菜单里的动态数据一律 TTL 记忆 + 后台刷新；**UI 线程上不许有 DB 查询**。
