# 本机下载 GitHub Release 资产的可用通道（2026-09-25 实测）

## 环境事实
- 沙箱出网走代理 `https_proxy=http://127.0.0.1:4699`
- **`github.com` 超时**（HTTP 000），release 资产不可直连
- **`api.github.com` 可达**（HTTP 200）→ 可用 API 拿资产的签名直链与 sha256
- **PyPI 阿里云镜像可达** → pip 可装（moderngl / glfw / numpy / imageio-ffmpeg / bpy 都是这么装的）
- `download.blender.org` **403**；`downloads.tuxfamily.org` 与国内 4 个 Godot 专题镜像 **404**
- 高校的 `github-release` 通用镜像（NJU/USTC/TUNA）对 godot **404**

## ✅ 通道 A：官方 CDN 签名直链（推荐，最干净）
```bash
# 1) 由 API 拿 302 的 Location（不经 github.com）
LOC=$(curl -s --noproxy '*' -D - -o /dev/null -H "Accept: application/octet-stream" \
  "https://api.github.com/repos/<owner>/<repo>/releases/assets/<asset_id>" \
  | grep -i '^location:' | sed 's/^[Ll]ocation: //' | tr -d '\r')
# 2) 从 release-assets.githubusercontent.com 直接下
curl -L --noproxy '*' -o out.zip "$LOC"
```
- 资产 id 与 **sha256** 都能从 `releases/tags/<tag>` 的 `assets[].id` / `assets[].digest` 拿到
- 缺点：**慢**（Godot 86MB 实测约 105 KB/s）
- 签名**有有效期**（约 1 小时），过期需重新取

## ✅ 通道 B：ghproxy 类加速（快，但经第三方）
```
https://ghproxy.net/https://github.com/<owner>/<repo>/releases/download/<tag>/<file>
```
- 实测 206，首字节 2.6s（比通道 A 快）
- **必须用官方 sha256 校验**（第三方可能篡改）
- `gh-proxy.com` / `ghfast.top` 也通；`ghproxy.cc` / `gh.llkk.cc` 不通

## ⚠️ 关键坑
- **`curl` 必须加 `--noproxy '*'`**，否则走代理会失败
- **Python urllib 默认走代理 → 502**；要让 Python 直连需 `no_proxy='*' NO_PROXY='*'`
- Git Bash 的 curl 走 **schannel**，对某些 CDN 报
  `schannel: server closed abruptly (missing close_notify)`；换 `--http1.1` 或改用 Python 不一定解决，
  优先换通道
