# 桌宠跨 Agent 体验设计 · 跟随模式

> **定位**：用户用自己的方式切换 AI agent（Alt+Tab / 点任务栏 / 切终端），
> 桌宠**被动跟随**，并在切换过程中保持体验连续。
>
> **与 `多agent切换设计.md` 的关系**：那份文档解决"桌宠作为切换器"（手动聚焦/激活/接管），
> 属于**兜底能力**；本文档解决"用户自己切、桌宠跟随"，属于**主路径**。
> 两份共享同一套身份与视觉层（常驻徽章 + 领结身份色 + 状态分层）与同一套交接机制（L1/L2），
> 本文不重复，只标注差异点。

---

## 0. 一句话方案

**桌宠不指挥你怎么切，但它跟着你切，并且把碎片化的多 agent 使用缝成一条连续的体验。**

三个支柱：

1. **跟随（Follow）**：焦点驱动，自动认出"你现在在跟谁"——零操作；
2. **无感（Seamless）**：跟随只换"身份"，绝不动位置、大小、动效相位、窗口；
3. **连续锚点（Continuity）**：桌宠是唯一一直看着全部 agent 的东西 → 承载跨 agent 的统一时间线。

---

## 1. 场景重新定义

| | 切换器模式（前一份文档） | **跟随模式（本文档·主路径）** |
|---|---|---|
| 谁发起切换 | 用户操作桌宠 | 用户用自己的方式切，桌宠**跟随** |
| 桌宠的角色 | 控制器 | **环境伴侣 / 状态镜像** |
| 用户成本 | 要学桌宠的交互 | ≈ 0（不需要改变任何习惯） |
| 主风险 | 单击语义变更、误触 | **跟错**（显示 A 而你在用 B） |

结论：**两条路径都要，但优先级不同**——跟随是主路径（覆盖日常 90%），
手动切换是跟随失效时的兜底（前台窗口识别不到、或无窗口的 CLI agent）。

## 2. 核心机制：跟随

### 2.1 焦点 → agent 的推断

**好消息：现成的地基已经有了。** `wb_whale_win._refresh_wb_hwnd()` + `_is_wb_focused(now)`
已经在做"前台窗口是不是 WorkBuddy"，用的是标题关键字（`WB_HOST_TITLE_HINTS`）。
把它从"单个 host"泛化为"**前台窗口属于哪个 agent**"即可。

**三级探测（沿用现有稳健做法，逐级降级）**：

| 级 | 手段 | 说明 |
|---|---|---|
| 1 | `GetForegroundWindow()` → `GetWindowThreadProcessId` → 进程名 | 最准，先匹配进程 |
| 2 | 窗口类名 / 标题关键字 | 兜进程名不足的场景（如 Electron 应用进程名一样） |
| 3 | **保持当前 / 进入未知态** | 见 §2.3——**不要猜** |

Agent 名片新增字段（对应 `agents/base.py` 的扩展）：

```
runtime.window_hints = {
    "proc_names":  ["Codex.exe", ...],
    "class_names": [...],
    "title_hints": ["Codex", ...],
}
```

### 2.2 触发方式与开销（⚠️ 有血泪教训）

| 方案 | 时延 | 开销 | 评价 |
|---|---|---|---|
| 复用现有 1s tick 轮询 | 最差 1s | 极低 | **太迟**——Alt+Tab 后等 1s 才更新，会觉得桌宠"迟钝" |
| 缩短 tick 到 250ms，只轮询 `GetForegroundWindow()` | ≤ 250ms | 极低（该调用极廉价） | ✅ **推荐兜底** |
| `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` 事件驱动 | 即时 | 零轮询 | ✅ **推荐首选**（不可用时退化到上面那行） |

> ⚠️ **事件回调里绝不能做重活**。这是本项目踩过的坑的变体（曾把带超时的网络探测放进消息循环，
> 结果消息循环每秒被卡死半秒、拖动不跟手）。回调里**只记录 hwnd + 时间戳**，
> 真正的身份解析（进程名匹配、名片查找）放主循环。

### 2.3 跟不到的时候：**保持未知态，不要猜**

这是我认为最容易被做错的地方。前台窗口是浏览器、记事本、文件管理器时：

- ❌ 不要"猜一个最可能的 agent"
- ❌ 不要"保持上一次但不做任何标记"
- ✅ **进入明确的未知态**：徽章半透明 + 领结回到默认色

理由：**猜错的代价远大于不猜。** 用户瞄一眼桌宠以为"现在在 Codex"，实际在别处——
这种错误归因会让人对桌宠失去信任，而信任一旦掉了很难挽回。
未知态虽然"没信息"，但它是**诚实的**。

### 2.4 去抖（防闪）

用户 Alt+Tab 快速扫过几个窗口时，前台会**连续变化**。如果不做去抖，
桌宠会在 300ms 内闪烁三次领结颜色——非常廉价。

- **去抖窗口建议 300–500ms**：窗口内多次前台变化 → 只认**最终停留**的那个。
- **一次 Alt+Tab 的目标：徽章变化 ≤ 1 次**（这条直接进了指标，见 §6）。
- 宁可"慢一点"也不要"闪"——迟 200ms 没人察觉，闪 3 次一定被骂。

## 3. 无感：切换时"什么变、什么不变"

这是本文档最该被实现者牢记的一张对照表。

### 3.1 变 / 不变

| 维度 | 跟随切换时 | 说明 |
|---|---|---|
| 领结身份色 | **变** | 身份的主载体 |
| 徽章（图形 + 实心/描边） | **变** | 身份的确认载体 |
| 气泡文案（抬头、用量、状态） | **变** | 数据跟随聚焦 |
| **窗口位置 / 大小** | **绝对不变** | 位置是用户的肌肉记忆，动了就是干扰 |
| **呼吸 / 眨眼 / 漂浮的动效相位** | **绝对不变** | 切换是叠加在动画上的一层，不是重启动画 |
| **hwnd / 窗口重建** | **绝对不重建** | 严禁调 `_recreate_window()` |
| 立绘形态（表情/朝向） | 温和过渡 | 不要"消散再重聚"，那会有"换人"的割裂感 |

> 一句话：**跟随带来的变化，应该是"同一只桌宠换了领结"，而不是"桌宠被替换了"。**

### 3.2 动效时长：跟随要比手动**更短**

| 场景 | 建议时长 | 理由 |
|---|---|---|
| 手动切换（用户主动发起） | 350–600ms | 有仪式感，用户期待反馈 |
| **跟随切换（用户没主动要求）** | **180–300ms** | 不是你发起的，长了就是噪音 |

### 3.3 快速往返要"退化"

用户在两三个 agent 之间反复对照（**极常见**：同一个问题问三家看谁答得好）时，
如果每次都播"徽章弹入 + 立绘过渡"，会非常吵。

**规则**：同一个 agent 在 **N 秒内被再次聚焦**（如 5s）→ **退化为纯颜色渐变**，
不播徽章弹入、不动立绘。只在"进入一个较长时间没去的 agent"时才播完整过渡。

这条规则的价值：让"高频往返"这个最常见的行为**几乎不可见**，把视觉预算留给真正重要的状态（§4）。

## 4. 连续锚点：桌宠独有的、也最容易被忽略的价值

### 4.1 用户切换 agent 时，真正丢的是什么

不是上下文（那个可以给摘要），而是**整体感**：

- 在 A 里问了一件事，切到 B 又问一遍，回来忘了 A 说到哪；
- "今天到底干了什么"——散落在 4 个 agent 的 6 个会话里，谁也说不清；
- 每个 agent 只知道自己那一段，**没有一个视角知道全部**。

**桌宠是唯一一直看着这一切的东西**——这是它相对"每个 agent 各一个窗口"的结构性优势。
把它用起来，就是从"多 agent 很碎片"变成"我用了一个团队"。

### 4.2 跨 Agent 统一时间线

**数据已经有了，零新链路**：`v_turn_total` 里有 `agent` 列 + `first_time` + `project` + `title`，
按时间排序就是跨 agent 的统一时间线。

| 呈现 | 内容 |
|---|---|
| 气泡第三行 | 从"活跃 X 分钟前"升级为跨 agent 的连续叙述，如「今天：Codex 3 轮 · WorkBuddy 12 轮」 |
| 长按 / 右键面板 | **统一时间线**：按时间顺序列出今天的每一轮（无论属于哪个 agent），点条目 → 开看板对应位置 |
| 看板顶栏 | 已有 agent 筛选，补一个「时间线」视图即可复用现有接口 |

**这是"跟随模式"真正的差异化价值**——跟随只是让体验不错，时间线才让用户觉得"这个东西留下来有意义"。

## 5. 接续（Handoff）在跟随场景下的正确形态

跟随模式下，"A 里没说完、想在 B 里继续"是高频需求，但**绝不能自动弹问**。

| 环节 | 设计 | 理由 |
|---|---|---|
| 检测 | 刚离开的 agent 有"似乎未结束"的会话（如最近一轮结束 < 2min 且无后续活动） | 纯本地推断 |
| 提示 | **徽章加一个极小的角标**（不是弹窗、不是气泡文案） | 切换时不该被塞信息 |
| 生成 | **用户长按/右键点击后才生成**交接摘要 | 省算力 + 零隐私风险 |
| 注入 | 按目标 agent 能力降级（直接注入 / 写 `handoff.md` / 复制剪贴板） | 同前一份文档 §5 |
| 脱敏 | 复用 `wb_common` + 看板 `mask()` | **强制**，摘要含提问原文 |

**原则：桌宠永远不替你做决定。** 切换体验要"零意外"——不弹窗、不问是非题、不自动提交。

## 6. 评估指标（跟随模式专属）

### 6.1 北极星

> **误跟随率**：桌宠显示 A、而用户实际在 B 的时间占比。**越低越好（目标 < 3%）。**
>
> 它直接衡量"跟随到底靠不靠谱"，且是唯一能同时反映**识别错误**与**去抖失效**的指标。

配套的"价值型"指标：

> **跨 Agent 时间线使用率**：用户打开统一时间线 / 从时间线跳转看板的比例。
> 它回答"连续锚点这个价值用户认不认"，而不是"功能有没有做出来"。

### 6.2 指标表

| 层 | 指标 | 定义 | 目标 |
|---|---|---|---|
| **跟随质量** | **误跟随率** ★ | 显示与实际不一致的时间占比 | < 3% |
| | 跟随正确率 | 显示的 agent == 实际在用的比例 | > 95% |
| | 跟随时延 | 前台切换 → 身份可见（P50/P95） | P95 < 250ms |
| | **切换闪烁次数** | 一次 Alt+Tab 期间徽章变化次数 | **≤ 1** |
| | 未知态占比 | 前台不属于任何 agent 的时间占比 | 仅观察（反映用户工作分布） |
| **连续性价值** | 时间线打开率 ★ | 打开统一时间线的频次 | 上升 |
| | 时间线跳转率 | 从时间线条目跳到看板的比例 | 上升 |
| | 跨 agent 会话占比 | 一天内涉及 ≥2 个 agent 的天数比例 | 仅观察 |
| **打扰** | **主动打扰次数** | 切换过程中桌宠发声 / 弹提示的次数 | **必须为 0** |
| | 误触率 | 无意图的桌宠操作 | < 2% |
| **接续** | 角标展开率 / 摘要采纳率 | 用户是否认可"未完成"提示 | 观察 + 上升 |
| **技术** | 前台探测开销 | CPU 增量 | 无感 |
| | 切换动效掉帧 | 守住 15fps 基准 | 不劣化 |

### 6.3 采集方式

沿用现有埋点（`_report_event()` → `%TEMP%\wb-hover.events.log`），新增：
`follow_change`（含 from/to/耗时）、`follow_unknown`、`follow_debounced`、
`timeline_open`、`handoff_badge_shown` / `handoff_expand`。

「误跟随率」需把 events.log 与用户在 agent 侧的活动（`v_turn` 的轮次时间）按时间对齐——
**判据**：某时刻桌宠显示 A，但该时间窗内有 B 的新轮次记录 → 计一次误跟随。

> 注意：events.log 是纯文本追加，长期分析前需加日切/轮转（参考数仓膨胀的教训）。

## 7. 设计取舍

| # | 取舍 | A | B | 建议 | 理由 |
|---|---|---|---|---|---|
| 1 | 跟随 vs 手动 | 全自动跟随 | 全手动 | **默认跟随 + 可锁定（pin）** | 跟随省事但可能跟错；给用户一个"暂时锁住"的出口 |
| 2 | 跟随灵敏度 | 快（灵敏，易闪） | 慢（稳，迟钝） | **去抖 300–500ms** | 宁可晚 200ms，不要闪 3 次 |
| 3 | 跟不到时 | 猜最可能的 | 保持未知态 | **未知态** | 猜错比不猜更糟，会毁掉信任 |
| 4 | 切换动效时长 | 与手动一致（有仪式） | 更短（跟随专属） | **跟随 180–300ms** | 不是用户发起的，长了就是噪音 |
| 5 | 高频往返 | 每次都播全套 | 退化为颜色渐变 | **退化** | 对照多个 agent 是高频行为，不该被动画打断 |
| 6 | "有未完成会话"提示 | 气泡显示（显眼） | 徽章角标（克制） | **角标** | 切换时不该被塞信息 |
| 7 | 交接摘要 | 自动生成并展示 | 用户触发才生成 | **用户触发** | 省算力 + 零隐私风险 |
| 8 | 桌宠的位置/动效相位 | 跟随切换时重置（"刷新感"） | 绝不改动 | **绝不改动** | 位置是肌肉记忆；相位重置会显得"卡了一下" |
| 9 | 未知态的视觉 | 完全不变（无感知） | 明确变灰 | **明确变灰** | 诚实 > 好看；用户需要知道"现在没跟着" |
| 10 | 探测实现 | 事件钩子（即时） | 轮询（简单） | **钩子优先，轮询兜底** | 钩子有平台差异，必须有退路 |

## 8. 分阶段实施计划

> 与 `多agent切换设计.md` 的阶段对应关系已标注。**P1 换了内容**：从"手动手动切换"改为"跟随"。

### P0 · 地基（不变，与另一文档的 P0 相同）

| 项 | 内容 |
|---|---|
| 范围 | `agents/base.py` 扩展：`vendor/glyph/accent` + **`runtime.window_hints`** + `capabilities`（默认值向后兼容，现有源零改动）；聚焦状态持久化到 `.whale_settings.json` |
| 交付物 | CLI 能列出每个 agent 的身份 / 可用性 / 窗口特征 / 能力 |
| 验收 | 现有 7 项桌宠测试 + 看板测试全绿不回归 |
| 风险 | 低（纯数据层） |

### P1 · 跟随（M）★ 主路径，价值拐点

| 项 | 内容 |
|---|---|
| 范围 | 前台探测（`SetWinEventHook` 优先，250ms 轮询兜底，**回调只记 hwnd**）；去抖 300–500ms；未知态；**无感身份切换**（严格按 §3.1 的"不变"清单：不重建窗口、不动位置、不重置动效相位）；跟随动效 180–300ms；高频往返退化 |
| 交付物 | 切窗口即跟随；埋点 `follow_change` / `follow_unknown` / `follow_debounced` |
| 验收 | 跟随时延 P95 < 250ms；**一次 Alt+Tab 徽章变化 ≤ 1 次**；拖动不卡（回归）；未知态不猜测 |
| 风险 | ⚠️ 钩子回调做重活会卡消息循环（有历史教训）→ 回调只记录，解析放主循环 |

### P2 · 连续锚点（M）★ 差异化价值

| 项 | 内容 |
|---|---|
| 范围 | 跨 agent 统一时间线：气泡第三行改为跨 agent 叙述；长按/右键面板列出今日全部轮次（`v_turn_total` 按时间排序，零新链路）；点条目跳看板 |
| 交付物 | 桌宠成为"唯一知道全局"的视角；埋点 `timeline_open` |
| 验收 | 打开率可测；面板数据与看板一致 |
| 风险 | 低。纯查询 + 呈现 |

### P3 · 手动兜底（M）—— 原"切换器"方案降级到此

| 项 | 内容 |
|---|---|
| 范围 | 手动聚焦切换（单击轮换 / 滚轮 / 右键）+ **锁定（pin）**：锁定后不被跟随覆盖；全局热键 |
| 交付物 | 跟随失效（无窗口 agent、识别不到）时仍可切换 |
| 验收 | pin 状态下跟随不生效（明确的行为边界）；切换步数 ≤ 2 |
| 风险 | 单击语义仍需重分配（见另一文档 §3.2），提供可配置开关 |

### P4 · 接续（L）

| 项 | 内容 |
|---|---|
| 范围 | 未完成会话检测 → 徽章角标；用户触发才生成交接摘要（复用数仓 + 脱敏）；按 `can_inject` 降级注入 |
| 交付物 | 跨 agent 接续；埋点 `handoff_badge_shown` / `handoff_expand` / `handoff_accept` |
| 验收 | 摘要必过脱敏；**全程无主动打扰**（不弹窗、不自动展示） |
| 风险 | 隐私（必须用户触发 + 确认）；各 agent 注入方式差异大（按能力降级，不做统一承诺） |

### P5 · 个性化（不变）

| 项 | 内容 |
|---|---|
| 范围 | `agents/<key>/persona.json` 覆盖层（accent / glyph / tones / motion / idle），引擎仍是 `wb_motion.py` 单一出处 |
| 交付物 | 不同 agent 有不同"接待风格"，但人设一致（古见始终是古见） |
| 验收 | 新增 agent 只需加一个 json，不改业务代码 |
| 风险 | 低；红线：persona 不能覆盖核心行为（古见几乎不说话） |

### 依赖与优先级

```
P0 ──┬─→ P1（跟随·主路径）──→ P2（连续锚点·差异化）
     │            └──────────→ P4（接续）
     ├─→ P3（手动兜底，可与 P1 并行）
     └─→ P5（个性化，最后做）
```

**若只能做一件事：做 P1。** 跟随跑通了，"多 agent 用起来不乱"这个核心体验就成立了。
**若有第二件事：做 P2。** 它把"体验不错"升级为"这个东西有独特价值"。

## 9. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 钩子回调卡消息循环 | 回调只记 hwnd + 时间戳，解析放主循环（历史教训的直接应用） |
| `SetWinEventHook` 在部分环境不可用 | 250ms 轮询兜底；再不可用则关闭跟随并明确提示 |
| 跟随过于灵敏导致闪烁 | 去抖 300–500ms + "一次切换徽章变化 ≤ 1" 作为验收指标 |
| 跟错导致错误归因 | 未知态而非猜测；误跟随率作为北极星持续监控 |
| 频繁重建窗口导致位置/相位重置 | **严禁在跟随路径调 `_recreate_window()`**，并入回归测试 |
| 隐私顾虑（桌宠知道你在用什么程序） | 全部本地推断不外发；README + 设置里明确说明；提供关闭开关 |
| 新功能破坏既有功能 | 每阶段跑全量回归（7 项桌宠测试 + 看板前端测试）；功能用 `*_ON` 总开关回滚 |
