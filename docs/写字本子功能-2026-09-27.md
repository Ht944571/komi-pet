# 写字本子：任务进行中写字 / 完成后展示（2026-09-27）

> **需求**：有对话任务在进行时，桌宠像参考视频里那样在本子上写字；任务完成后把写好的本子展示给用户。
> **参考**：`Q版古见同学写字.mp4`（4.12s / 24fps / 832×1108）。
> ⚠️ 该视频是 AI 生成的，**画面带「AI生成」水印** —— 按项目红线**只当动作参考**，
> 素材一律自己画（`tools/make_notebook.py`）。

---

## 1. 参考视频拆成三段

| 阶段 | 帧 | 画面 |
|---|---|---|
| **写字** | #0–79（0~3.3s） | 坐着抱一本棕色本子在胸前、低头，身体轻微起伏摇摆 |
| **翻页** | #82–89（3.4~3.7s） | 本子抬起翻转，露出亮白内页 |
| **展示** | #89–96（3.7~4.0s） | 翻开的本子对着镜头，白页上有**手写线条**，页脚一颗粉色小爱心 |

## 2. 触发条件：**与气泡 OK 态共用同一个判据**

这是整个设计里最重要的一条。气泡的"完成态"早就靠 `_sync_bubble_mode()` 里的
`prev_active_n > 0 → 0` 触发；本子**另算一套判据迟早会和它对不上**
（"气泡说完成了、本子还在写"这种自相矛盾比不做还糟）。

所以本子的驱动就写在**同一个函数里的同一处**：

| 事件 | 判据 | 本子动作 | 时长 |
|---|---|---|---|
| **任务开始** | `len(active) > 0`，此前 hidden | `appear`：拿出本子、翻开 | 0.32s |
| **进行中** | `len(active) > 0` 持续 | `writing`：逐行落墨，写满一页翻页 | 每行 ~0.62s |
| **任务完成** | `prev > 0 且 len(active) == 0`（**与 OK 气泡同一条件**） | `present`：翻页 + 举起本子展示 | 0.42s，保持 6s |
| **新一轮开始** | `len(active) > 0` 时正处于 present | 收起旧页 → 直接接着写（**换新一页**） | — |

两个刻意的细节：

- **首次取样只建基线**（`prev is None` 时不触发）。否则桌宠启动那一瞬间，
  已经在跑的任务会被误判成"刚刚开始"，凭空播一次拿出动作。这个做法是跟气泡 OK 态学的。
- **任务完成后的统计要留住**：`active` 一空，数据就没了。所以 `writing` 期间每 tick
  把最新统计刷进状态机，展示页用的是**最后一帧的真实值**，不是编的。

## 3. 动作表现

### 写字
- 本子**摊开**抱在胸前（内容高的 0.58 处起），微微向内倾 9°，随手腕**起伏**（±1.1px / 1.9Hz）
  并轻微左右摆（±0.8°）—— "持续在写"的活气全靠这组微动。
- **墨迹逐行从左长出来**：每行 0.62s、行内 0.34s 写完；行首有缩进，每 4 行来一次段首，
  行宽 0.52~0.94 随机（**确定性伪随机**，不用 `random`，测试才能逐帧复现）。
- 正写的那一行末端点一个**略大的笔尖墨点** —— "她在写"的读感主要靠它。
- **跳过中缝**：跨中缝写字物理上不对，凑近看很假。

### 翻页
- 写满 9 行 → 翻页：本子**横向压扁再弹回**（0.30s）。2D 里这比真做纸张翻转便宜得多，
  读感一样。
- **挂起/睡眠也不丢行**：推进按"累计行数"，恢复后一次性补齐（实测挂起 60s → 97 行 / 第 11 页）。
  ⚠️ 推进判据**必须用累计行数**（`total_lines`）而不是本页行数（`lines`）——
  后者每满一页归 1，`while want > lines` 会**永远追不上 → 死循环 → 卡死桌宠的消息循环**。
  这是实测抓到的，别再改回去。

### 展示（翻页的"翻"）
- 本子从写字位**升起**（上沿 0.58 → 0.50）、**转正**（倾角 9° → 0°）、**放大** 1.25 倍，
  带一点过冲弹回 —— 这一步就是参考视频里的"翻页"读感。
- 页上：**写满的整页手写墨迹** + 页脚**可读的真实结果** + 一颗小爱心（呼应末帧）。

## 4. 展示形式（"写好的本子"具体长什么样）

```
        ┌──────────────────────────────┐
        │ ～～～～～～～～～～～～～～    │   ← 手写墨迹（整页写满）
        │   ～～～～～～～～～～～～～    │      跳过中缝，两侧都不压线
        │ ～～～～～～～～～～～～       │
        │   ～～～～～～～～～～～       │
        │  8:32 · 1.2万 tokens · 3.4 积分  ♥ │   ← 真实数据 + 小爱心
        └──────────────────────────────┘
```

- 页脚数据来自**当前会话**：用时（`first_ts → now`，与气泡同一口径）、累计 tokens、累计积分；
  标题留给日志/上报（页宽太小就只画爱心不画字 —— 字号糊成一团不如不画）。
- **点本子 → 打开完整看板**（写在本子上的东西，看板里有明细）。
  只有展示态接点击；写字态不抢 —— 那属于身体互动（摸头/戳脸/戳裙子）。

## 5. 几何：两条硬约束

本子位置**一律按立绘内容框动态算**（`deck()`），不许假设画布边界 ——
v3 八态内容顶差别极大（0.041~0.489），写死会把本子画到脸上。

| 约束 | 规则 | 为什么 |
|---|---|---|
| **不遮眼睛** | 本子上沿 ≥ 该态眼位 + 1.5% | 八态眼位差很大（idle 0.468 / stone 0.510 / pout 0.533 / blush 0.577），**写死一个比例必然遮住某几个态的脸**。眼位来自 `_eye_config.json`，走 `_face_metrics()` |
| **不出窗口** | 宽度 ≤ 内容宽 62%（展示）/ 46%（写字）；底部不越过角色脚下 | 跨页素材是横版（宽高比 1.36），只按高度等比放大就会宽过她的肩膀；分层窗口外就是"被切掉" |

> 第一版就是在**中心定位**下放大 → 上沿顶到脸上，把眼睛盖住了。
> 改成**用上沿定位**后才可控。

## 7. 踩过的坑（都写进代码注释了）

1. **ARGB 少了 Alpha 通道** ✗：`INK = 0x746556` 只有 6 位 → alpha=0 →
   **墨迹全透明**，GDI+ 照画不报错。表现是"页面上只有爱心看得见"（爱心恰好写的是 `0xFFE58AA0`）。
   项目里所有颜色都必须带 `0xFF`。
2. **推进判据用错变量 → 死循环**（见 §3 翻页）。
3. **GDI+ 旋转贴图的源矩形**：`GdipDrawImagePointsRect` 的 `srcwidth/srcheight`
   必须给**图片实际尺寸**，给成目标尺寸只会取左上角一块。
4. **`insert_after` 的锚点在方法体里**：批量插代码时缩进跟着锚点走，结果整段落进上一个方法内部
   （**语法仍然通过** —— 变成了嵌套函数）。→ 插完必须用 `ast` 校验"方法确实在目标类里"。

## 追加：AI 视频帧序列层（2026-09-27 深夜）

用户明确要「视频的效果」——于是把**同一段参考视频本体**（他生成的那条）接进了桌宠：

    视频逐帧解码 → 项目算法抠图（边界连通洪水，白底也不会把脸/书页抠穿）
    → 裁掉底部水印条 → 按 v3 立绘高度对齐缩放（0.68，内容高 0.642 vs v3 0.639）
    → 49 帧透明 PNG（存储 420x565，共 6.3MB）+ _anim_meta.json

播放：（相位→帧号，纯逻辑可单测）；
在「有任务在跑」时**整个角色换成视频帧**（写字段循环 / 翻页展示段播一遍），
程序化本子此时不画（视频里她本来就抱着本子，叠两层=穿帮）；气泡/命中区/视线照常
（帧序列有自己的内容框，登记为伪态 ）。

工具：。换一条视频就重新跑一遍即可。
