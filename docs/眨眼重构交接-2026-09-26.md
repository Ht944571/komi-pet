## 1. 一句话

**眨眼从「一个能用的循环动画」升级为「三层标准驱动、与用户交互联动」的生命感系统**：
节奏完全随机（3~8s／注视专注 8~12s／夜间再降）、时序改为快闭慢睁（≈230ms）、
新增受惊连眨／注视式慢眨／拖动回待机先眨眼／头部微点／夜间慵懒，
2D 与 3D 两条线共用同一套标准与同一份纯逻辑判定。

**状态**：✅ 2D 与 3D 均已落地并通过测试（全套 17 个测试文件全绿 + 3D 专项 16/16）。
**未覆盖**：需要 Live2D 四层结构 / 3D 骨骼 / 像素画布的部分（见 §5，属路线与资产限制）。

## 2. 本轮改了什么（双线对照）

| | 2D（GDI+ 立绘） | 3D（moderngl + morph） |
|---|---|---|
| 落点 | `wb_motion.BlinkScheduler` v2 + `wb_whale_win` 接线 | `wb_pet3d.Blink` v2（重写）+ `wb_pet3d` 接线 |
| 驱动 | 眼睛睁开度 ratio（1=开） | morph 权重 k（1=开，`1-k`=眼睑下压量） |
| 节奏 | 3~8s／8~12s／夜间 ×1.9 | 3~8s／8~12s／夜间 ×1.8 |
| 时序 | 65 / 30 / 135 ms（≈230ms，快闭慢睁） | 0.065 / 0.030 / 0.135 s（同规格） |
| 部分眨眼 | 65% 只闭到 40–70%（无保持段） | 65% 只压一半（bottom=0.45） |
| 双连眨 | 12%，间隔 0.18s | 12%，间隔 0.18s |
| 受惊连眨 | `startle()`：点击头/脸触发 | `startle()`：单击戳触发 |
| 回待机先眨眼 | 拖动结束调 `blink_now()` | 左键拖动松手调 `blink_now()` |
| 注视式慢眨 | 鼠标悬停 → attention（8~12s） | 光标在窗口附近 → attention（8~12s） |
| 夜间 | 频率降 **+ 常驻半眯眼 30%** | **仅频率降**（半眯眼停用，见 §6 坑 1） |
| 头部微点 | `nod()` 包络 × 1.5px，叠加进呼吸 | 未做（3D 有 gaze/呼吸，未叠加眨眼联动） |

### 关键参数（唯一出处：`wb_motion.py`，红线：数字只写这里）

```
BLINK_MIN_S/MAX_S/MEAN_S      3.0 / 8.0 / 3.6     常态（≈16 次/分）
BLINK_ATTENTION_*             8~12s（均值 9.5）    注视/专注
BLINK_NIGHT_MEAN_FACTOR       1.9                  夜间频率降
BLINK_CLOSE/HOLD/OPEN_S       0.065 / 0.030 / 0.135  快闭·1帧·慢睁
BLINK_PARTIAL_PROB/DEPTH      0.65 / 0.40–0.70      部分眨眼
BLINK_DOUBLE_PROB/GAP         0.12 / 0.18           双连眨
BLINK_STARTLE_GAP_S           0.05                 受惊连眨（start-to-start <300ms）
BLINK_LOWER_LID               0.10                 下睑辅助上抬（上睑主导）
BLINK_NOD_PX                  1.5                  眨眼伴随头部微点
BLINK_NIGHT_DROOP             0.30                 夜间半眯眼（仅 2D）
```

## 3. 三层标准 → 落地情况（逐条）

### 一、通用核心标准

| 标准 | 状态 | 证据 |
|---|---|---|
| 间隔完全随机 3~8s（禁固定周期） | ✅ | `test_blink_modulation` A0/A0b/A3（方差 >0.5） |
| 注视/专注 8~12s | ✅ | A1 + `test_blink_modulation` F1–F3 |
| 快闭慢睁（150~250ms，闭 30%／全闭 1 帧／睁 60%） | ✅ | `test_blink_smooth` A1–A4b、D1–D3 |
| 上睑主动、下睑仅轻辅助 | ✅ | `BLINK_LOWER_LID=0.10`（原 22%） |
| 随机双连眨 10~15%（<300ms） | ✅ | 12% / 0.18s；`test_blink_modulation` G 段 |
| 眨眼伴随头部微点 1~2° | ✅ 2D（1.5px 包络）／⬜ 3D | `nod()` + `test_blink_modulation` I 段 |
| 眉毛随眨眼下压 1~2px | ⬜ **未做** | 立绘是整张位图，无独立眉毛层（见 §5） |
| 不与呼吸同频（防节拍器） | ✅ | 间隔完全随机 + 相位随机，无固定耦合 |

### 二、分技术路线

**2D（立绘路线，对标 Live2D 项）**

| 标准 | 状态 | 说明 |
|---|---|---|
| 上睑主导 + 下睑 10% | ✅ | `_draw_blink` 下睑量取 0.10 |
| 部分眨眼（不总是全闭） | ✅ | 65%，深度 40–70% |
| 瞳孔/眼球层独立（贝尔现象：闭眼上转） | ⬜ **未做** | 立绘静态，眼珠无独立层 |
| 睫毛层随眼睑弯曲、不穿模 | ⬜ **不适用** | 睫毛画在立绘里，无独立层 |
| 正片叠底混合表情参数 | ⬜ 不适用 | 本项目表情=换立绘，非参数混合 |
| 参数两端 0.1 缓冲（防极限抖动） | ⬜ 未用 | `BLINK_BUFFER=0.10` 已定义未消费（当前无极限抖动问题） |
| 60fps / 8–12 关键帧 | ➖ 平台约束 | 2D 定在 15fps（66ms/帧）——**曾是刻意的风格选择**（低帧率量化更像赛璐璐）；眨眼 230ms ≈ 3.5 帧 |
| ≥5 种情绪差异化眨眼 | ⚠️ 部分 | 已有：平静／开心（眯眼让位）／受惊（双连眨）／困倦（慢眨）；**害羞、惊讶的专属眨法未做** |

**3D（萌系模型路线）**

| 标准 | 状态 | 说明 |
|---|---|---|
| 眼睑独立骨骼 | ⬜ **未做** | 当前是 morph target（模型只有形态键，见 §5） |
| 眼皮贴合眼球曲面无穿模 | ⚠️ 勉强 | 平板 morph，大图可见边缘（文档 P1 已记） |
| 闭眼时眼球自然上转 | ⬜ 未做 | 需眼珠独立节点 |
| 睫毛/刘海物理跟随 | ⬜ 未做 | 需物理或额外骨骼 |
| 眼皮厚度与阴影 | ⬜ 未做 | 模型侧问题（P1） |
| 高光随闭眼渐变消失 | ⚠️ 部分 | 全闭 morph 盖上时自然遮住，无渐变 |

### 三、交互级最高标准

| 标准 | 状态 | 证据 |
|---|---|---|
| 鼠标注视联动（抬头看光标 + 慢而轻的注视式眨眼） | ✅ | 2D attention + 注视带 8~12s；3D 按光标距离切 attention |
| 点击头/脸 → 受惊连眨 + 缩脖 | ✅ 连眨／⚠️ 缩脖 | 2D `_react` 已有形态切换（害羞/石化），3D `surprise` 有后仰；**未做专门的"缩脖"** |
| 移动/拖动回待机先眨一次 | ✅ | `blink_now()`（2D 拖动结束 / 3D 松手） |
| 夜间/低亮度 → 频率降 + 半眯慵懒 | ⚠️ 部分 | 2D：频率+半眯眼齐备；3D：仅频率（半眯停用）；**亮度读取不可移植 → 用时段 23:00–07:00 替代** |

## 5. 未完成项与后续（按可行性分级）

### 可做（不依赖新资产，推荐下一步）

1. **眉毛随眨眼下压 1~2px**（通用标准 §一.2）——2D 可在 `_eye_config.json` 增加眉毛锚点
   （复用 `calib_face.py` 网格标定流程），`_draw_blink` 里画一条淡压线；3D 需模型有眉毛 morph。
2. **害羞/惊讶的专属眨法**（分路线标准 §二.1「≥5 种情绪」）——害羞：快速两下 + 低头；
   惊讶：先睁大再单眨。落点：`_blink_vetoed` 同级加"情绪眨法表"。
3. **3D 头部微点**——`wb_pet3d.tick` 里把 `1-k` 乘一个小系数加到 `bob`（与 2D 的 nod 同思路）。
4. **"缩脖"动作**——2D/3D 均可在受惊时叠一个 `scale`/位移脉冲（现有 `surprise` 后仰是雏形）。
5. **参数缓冲（`BLINK_BUFFER`）真正消费**——目前定义未用；若将来出现极限位置抖动，
   在 `eye_opening_ratio` 两端夹一层缓冲。

### 需要资产/模型（做不了就如实记着）

6. **贝尔现象（闭眼眼球上转）**——需立绘拆层（眼珠独立）或 3D 模型加眼珠节点。
7. **睫毛层独立运动**——同上，需拆层。
8. **3D 眼睑骨骼 + 眼皮厚度阴影 + 刘海物理**——需重新绑骨/加形态键（模型侧工时）。
9. **2D 提帧到 60fps**——与"低帧率量化"的现有风格取向冲突，**建议维持 15fps**（这是刻意的美术选择，不是欠债）。
10. **屏幕亮度感知**——不可移植；当前用时段替代。若要，Windows 可读 `GetDeviceGammaRamp`
    或环境光传感器 API（平台相关，收益有限）。

## 6. 踩坑实录（本轮，改眨眼前必读）

1. **3D 夜间常驻半眯眼开局翻车**：morph 眼睑是**平板**，常驻压下 25% 看起来是两块白板 = 死鱼眼
   → 3D 停用常驻 droop（只保留频率降低），2D 的椭圆眼睑无此问题、保留。
   **教训**：同一个标准在两条线上要按渲染能力分别取舍，不能照抄参数。
2. **旧测试金值大面积翻转**：`test_blink_smooth` 的 0.099/0.066/0.165 是被取代的旧时序，
   `test_blink_modulation` 的 `BLINK_WORK_RATE_SCALE` 机制被"注视/专注间隔带"取代
   → 前者更新金值，后者整文件重写。**改标准就是改测试基线**，不要只改代码。
3. **`_refresh_interval_band` 必须在 tick 里持续刷新**：只在 `__init__` 调，标志（attention/night）
   变了带宽不更新 → 测试 A1 抓到。
4. **受惊连眨的间隔语义**：`BLINK_STARTLE_GAP_S` 是"主眨结束→第二眨开始"，
   最初误设为 0.12 导致 start-to-start 0.35s（> 300ms 标准），改成 0.05 达标（实测 0.29s）。
5. **bash heredoc 改代码不可靠**（本轮又被咬两次）：`AssertionError` 后**部分替换已生效**，
   导致"以为没改其实改了一半"。**改源码/长文档统一用 Edit 工具**。
6. **`_save_settings` 整体重写会抹掉别人的键**（上轮修的 `pet_mode`）——本轮相关：
   新字段（如未来加"眨眼强度"设置）同样要合并写入，别回退成整体覆盖。
