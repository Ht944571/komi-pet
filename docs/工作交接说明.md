## 1. 这是什么（30 秒版）

一个**纯标准库**（ctypes + GDI+）的 Windows 桌面项目，由两半组成：

1. **桌宠**：桌面角落常驻的「古见同学」Q 版小立绘，头顶气泡显示用量，
   有呼吸/眨眼/漂浮/鼠标跟随/拖拽吸附/双击摸摸头/右键菜单。
2. **多 Agent 用量看板**：把本机各个 AI Agent 的用量记录解析、汇总成本地网页
   （`http://127.0.0.1:8801`），**并按「哪些 agent 正在运行」让古见戴上不同配件**。

一句话记住这次的核心升级：**桌宠从"显示器"变成了"一只承载多个 agent 的角色"**——
哪个 agent 在跑，她就戴上对应的配件；多个同时跑就**同时佩戴**。

| 正在运行的 agent | 古见的表现 |
|---|---|
| WorkBuddy | 身边出现一只**小黑猫**，会溜达 / 坐下 / 玩耍 |
| ZCode | 自己戴上**复古小纽扣贝雷帽** |
| DeepSeek Harness | 抱着**鲸鱼玩偶** |
| **多个同时** | **上述配件同时佩戴** |

## 4. 架构：分层与契约

```
① 数据层  agents/   四个 agent，各自形态不同，统一输出「规范用量形状」
                      ↓
② 数仓层  wb_dw.py  全部是 VIEW（ODS 增量入库后聚合自动最新，无需重建）
                      ↓
        ods_jsonl_event（+ agent 列）   ods_jsonl_raw（原文归档）
                      ↓
③ 表现层  wb_api.py / dashboard.html   看板（顶栏可按 agent 切换）
          wb_accessories.py            配件层（按「哪些 agent 在跑」佩戴）

④ 活跃探测 wb_agent_presence.py  后台线程 → 配件层的输入
```

### 4.1 规范用量形状（最重要的一个契约）

所有聚合都建立在 `ods_jsonl_event.raw_usage_json` 上，VIEW 按**固定字段名**提取：

```
credit / prompt_tokens / completion_tokens / total_tokens /
prompt_cache_hit_tokens / prompt_cache_write_tokens /
prompt_cache_miss_tokens / completion_thinking_tokens
```

**每个数据源只需把自家用量归一到这个形状**，既有视图/接口/前端就能原样复用。
新增 agent 不必写一套 SQL。常量在 `agents/base.py` 的 `CANONICAL_USAGE_FIELDS`。

### 4.2 数据源的两种形态

| 形态 | 实现 | 现有 |
|---|---|---|
| **文件源** | `root()` + `glob_pattern()` + `parse_lines()`；采集器负责枚举/断点续采/覆盖检测 | workbuddy、codex |
| **自管源** | **覆盖 `collect()`** 自行读数据、构造规范行、调 `insert_rows()` | zcode（SQLite）、deepseek-harness（zstd 压缩流） |

自管源存在的理由：SQLite 表和压缩流**没有"文件 + 行号 + 游标"结构**，硬套按行契约会把接口拧歪。

**自管源必须幂等**：`line_no` 要用**内容派生的稳定整数**（52 位哈希），
用递增序号会在重采时错位产生重复行。

### 4.3 配件层的三个原则

1. **声明式**：哪个 agent 配什么、怎么探测、有哪些能力、**用户开不开它** → 全在
   `assets/_agents.json`（读取层 `wb_agent_registry.py`）。`_acc_persona.json` 降级为回退格式。
   **新增配件只加一行 JSON，不改代码**（严禁 `if agent == "zcode"`）。
2. **槽位化**：`head` / `arms` / `companion` 三槽互不冲突
   → 「多 agent 同时 → 配件并集」是自然结果，**没有任何特判**。
3. **几何与绘图分离**：`compute_placement()` 只算坐标，桌宠（GDI+）与预览（PIL）
   **共用同一份定位逻辑**，杜绝两处漂移。

### 4.4 「活跃」与「聚焦」是两个信号（重要设计取舍）

- **活跃**（决定配件）= 该 agent **进程/端口在运行**。语义是"我的生活里有它"，
  **必须稳定**——开着一整天就一整天都在。配件体积大、动静大，忽隐忽现非常廉价。
- **聚焦**（决定徽章/领结）= 前台窗口属于谁。可以频繁变化（轻量元素）。

当前实现只做了"活跃"（配件）；"聚焦"仍在设计文档里，未实现。

### 4.5 Agent 登记册（第四个契约，2026-09-25 新增）

`assets/_agents.json` 是「**谁在跑 / 配什么配件 / 有哪些能力 / 配置在哪 / 用户开不开它**」的
**唯一声明处**。读取层 `wb_agent_registry.py`，配件层与探测层都从它读。

```jsonc
{
  "agents": {
    "zcode": {
      "label": "ZCode", "enabled": true, "verified": true, "order": 15,
      "accessory": "beret", "accent": "#39406B",
      "caps":  { "log": true, "presence": true, "hooks": false },
      "presence": { "procs": ["ZCode.exe"], "ports": [] },
      "config_paths": ["~/.zcode/cli/config.json"],
      "log_paths":    ["~/.zcode/cli/db/db.sqlite"],
      "notes": "…"
    }
  }
}
```

**三条规矩**：
1. **新增 agent 只改这个文件**，不改代码。
2. **`enabled=false` 的项完全被忽略**（不探测、不配配件）—— 这是「用户自主选择接入」的落点。
3. **`verified=false` 表示本机未实测**（路径/进程名来自对同类项目的调研）。
   默认关闭，开启前需自行确认，否则只会空转。

注册表现状：**登记 11 个，启用 4 个**（workbuddy / zcode / deepseek-harness / codex），
其余 7 个是「已知但未验证」（claude-code / gemini-cli / qwen-code / kimi / cursor / opencode / codebuddy）。

**读写分离**：读走 `GET /api/registry`，写走 `POST /api/registry` →
`wb_agent_registry.set_enabled()`（白名单 + 备份 + 原子替换）。
**只写这个登记册，绝不碰任何 agent 自己的配置文件。**

## 5. 四个 Agent 的数据源

| agent | 位置 | 形态 | 坑 |
|---|---|---|---|
| **workbuddy** | `~/.workbuddy/projects/*/*.jsonl` | 文件源 | 基准源，`providerData.rawUsage` 本身就是规范形状 |
| **zcode** | `~/.zcode/cli/db/db.sqlite`（`model_usage`） | **自管源（SQLite，只读）** | 提问正文在 **`part.data`** 不在 `message`；`data.source.kind=plugin` 的是插件注入，要过滤 |
| **deepseek-harness** | `~/.dsh/sessions/**/session*.jsonl.zstd` | **自管源（压缩流）** | 见下三条 |
| **codex** | `~/.codex/sessions/**/rollout-*.jsonl` | 文件源 | 上下文在文件头（`session_meta`/`world_state`/`turn_context`）→ 需实现 `build_context()` |

### DSH 的三个坑（都写在代码注释里）

1. **多帧 zstd 会静默截断**。`zstandard.stream_reader()` 默认
   `read_across_frames=False` → **读完第一帧就停且不报错**。实测 3.96 MB 的文件只解出
   203 字节（恰好是会话头那一帧）。→ 用 `decompressobj()` + `unused_data` 逐帧续读；
   并在 `zstdio.read_zstd()` 里做**完整性校验**（JSONL 必须以 `}`/`]` 收尾），
   不闭合就继续试下一层——**截断不报错，只看"拿到非空 bytes"会被骗**。
2. **同一会话存在两种格式文件**（`session.jsonl.zstd` 与 `session.v3.jsonl.zstd`），
   直接扫会**重复计数**。→ 不猜哪个权威，而用**内容派生的稳定身份**
   （`hash("usage:<sid>:<turn>:<step>")`）让两种格式的同一事件折叠成同一键。
   实测产出 2835 行 → 入库 2703 条，差额就是折叠掉的重复。
3. **同一个 usage 对象混着两种口径**：
   `inputTokens/outputTokens/reasoningTokens` 是**单步增量**，
   `cacheReadTokens` 是**会话级累计**（跨轮从不重置）；`totalTokens` 与 in+out 对不上 → 不用。
   且 `inputTokens` **只含新增（未命中缓存）部分** → 单次真实输入 = `inputTokens + 缓存增量`。
   两条自洽校验必须成立：`cached ≤ prompt`、`total == prompt + completion`。

### zstd 依赖（只影响 DSH）

Python 3.13 **没有** stdlib zstd（3.14 才有 `compression.zstd`）。`zstdio.py` 做了**四层降级**：
① `compression.zstd` ② `zstandard`（当前生效，已装）③ `zstd` 命令行 ④ 全无 → 明确报告并跳过该源。

```bash
pip install -i https://mirrors.aliyun.com/pypi/simple/ zstandard     # 务必带镜像，默认源极慢
```

> 对照：Python 3.14 的 stdlib `open()`/`decompress()` **都会跨帧**；
> 与 `zstandard.stream_reader` 行为**相反**，别想当然。

## 6. 配件美术

**改美术前必读 `docs/配件美术规范.md`**。这里只给要点。

### 6.1 渲染语言（与立绘对齐）

立绘用的是「粗细分明的曲线描边 + 3 层硬边 cel + 沿轮廓亮边 + 低饱和配色」。
第一版配件是**纯色剪影**，所以像剪贴画——差的不是形状，是**渲染语言**。
因此先做了 `tools/artkit.py`（描边压在填充下 / cel 暗部 / 左上亮边 / 接地影 / 贝塞尔采样 /
渐变宽线 / `pie` 平底拱顶），再用它重画形体。

### 6.2 素材来源：程序化 vs 生成式

| 配件 | 来源 | 理由 |
|---|---|---|
| **小黑猫** | **程序化**（`acc_art.py`） | 需要 14 帧一致的动画，**生成式保证不了帧间一致性** |
| **贝雷帽** | **生成式**（ImageGen → `gen_to_asset.py` 抠图） | 静态单图；毡呢质感是图元拼不出来的 |
| **鲸鱼玩偶** | **生成式** | 静态单图；布偶的缝线/补丁/表情需要细节 |

分工原则：**多帧动画一致 → 程序化；静态单图要质感 → 生成式**。

### 6.3 生成式素材管线

```
ImageGen（提示词写死 artkit 色值） → tools/gen_to_asset.py（抠背景）
  → assets/_gen/cut_*.png → make_accessories.py 安装为 acc_*.png（+镜像 _f）
  → 重标 KINDS 的 pivot_y / ratio
```

- 提示词要点：把令牌**十六进制色值**写进提示词，并要求 clean dark line art + cel shading。
- **`background="transparent"` 不被满足**！返回 RGB 无 alpha 且把透明**画成棋盘格**。
  → `gen_to_asset.py` 判据：「中性且亮」+ **从边界连通传播**
  （连通传播不可省，否则物体内部的白色高光会被误伤成透明窟窿）。
- **换素材必须重标 `pivot_y` / `ratio`**（当前：贝雷帽 0.62、q 0.82 / alt 0.90），
  这些是目视标定值，无法自动推导。
- `make_accessories.py` **优先装生成式素材**，缺失时**自动回退** `acc_art` 程序化绘制。

### 6.4 摆放契约（防漂移）

`_acc_config.json` 由生成器产出，含**实测锚点**（head_top / head_w / chest_y …）
与**资产契约**（pivot_y）。运行时读取覆盖 `KINDS` 默认值。
**改画布尺寸后若不重生成，硬编码值会失配**——这条机制就是为了根治它。

| 配件 | 尺寸基准 | 比例 | 锚点 |
|---|---|---|---|
| beret | 实测头宽 | 0.82（Q 版）/ 0.90（高冷） | 发顶 |
| whale_plush | 实测头宽 | 0.56 | 胸口（底边） |
| cat | **立绘宽**（不能用头宽） | 0.34 | 地面（脚底） |

> Q 版的 `head_w` 实测是**头发**（0.945 立绘宽）而非头骨（约 0.56），
> 所以必须按风格修正比例，否则帽子会大得压住整个头。

### 8.8 眨眼状态调制 + 部分眨眼（眨眼标准 ④⑤ 层落地）
眨眼从"常数"升级为"跟着角色状态走"，所有数字只进 `wb_motion.py`（红线 2）：
- **工作中降频**（`BLINK_WORK_RATE_SCALE=1.6`）：会话 running 时间隔整体拉长
  ≈ 率降 37.5%（30–50% 区间中段）；均值与 σ 同步放大、上限随之放宽，避免分布被钳平。
- **禁眨否决**（`WhalePet._blink_vetoed`）：拖拽 / 悬停端详 / 按压及回弹 /
  OK 气泡弹入弹出动画 / 成功与欢迎情绪（让位眯眼笑）期间不开新眨眼；
  进行中的眨眼**跳到睁开段收尾**（禁眨 ≠ 定格成半闭眼），解除后从当下重排间隔、
  被打断的双眨不接回。
- **久无人慢眨**（`BLINK_SLOW_PROB=0.45`，时长 ×1.5–2）：idle 超过 30s 后偶发
  慢眨出"犯困感"；慢眨必定全闭——深而慢才像犯困。
- **部分眨眼**（`BLINK_PARTIAL_PROB=0.65`，深度 40–70%）：现实中六七成眨眼只闭
  四到七成，全闭反而少；部分眨眼上下睑不接触 → 无保持段、无睫毛接触线，总时长
  相应变短。调度器每次触发采样形态写入 `seg_close/seg_hold/seg_open/close_depth`，
  默认值 = 基准常量（旧的手动设 `blink_t0/blink_total` 的测试不受影响）。
- **签名量化修正**：动效签名的眨眼项从 `ratio>0.5` 改为 4 级量化
  `round(ratio*3)`——部分眨眼最低只睁 30–60%，旧判定会整段漏掉重绘（眼皮动了
  画面却不动）；4 级 ≈ 15fps 的 2–4 帧，与眨眼低帧率量化规格一致。
- 测试：`test_blink_smooth.py` G 段钉住部分眨眼概率（双眨调度公式本身未变）；
  新增 `tools/test_blink_modulation.py` 45 条覆盖上述全部行为（含 WhalePet
  实例级否决与 `_update_motion` 集成）。全套 10 个测试文件通过（py3.14 与
  托管 3.13.12 双运行时验证）。

### 8.9 面部叠加层美术优化（眨眼盖板 / 高冷版锚点 / 眼缝标定 v4）
真机 4× 面部特写（新工具 `tools/shot_face_frames.py`）暴露三个问题，全部修复：
- **高冷版（alt）眼部/腮红锚点全部失效**：v3 配置里 alt 6 态是占位 junk
  （cy≈0.15、w=0.05，指在刘海区）→ 高冷版**从不眨眼**、腮红画在头发上。
  新工具 `tools/calib_face.py`（网格叠加 → 读数 → 校验图闭环；含 sclera/暗域
  自动检测辅助）重标 alt 6 态 + Q 版 6 态复核，`_eye_config.json` 升 **v4**。
- **眼缝约定（v4 核心变更）**：眼框 = 上睑缘→下睑缘之间的**可见暗区**，
  盖板行程全部发生在"看得见的眼睛"上。旧版从"整眼框顶"下落，行程一半消耗在
  睫毛/头发区——**部分眨眼（40–70% 深度）在 Q 版上几乎不可见**（⑤ 号标准落空）。
- **盖板渲染三处**：① `BLINK_LID_REST=0.28`——盖板从立绘自带睫线带的下缘
  "钻出"，自带深色睫线保持可见充当闭眼上睑（旧版盖进刘海，发丝被"擦掉"）；
  ② 盖板色用各状态实测 `lid_skin`（眼底皮肤带均值，生成器产出）再向眼线色收
  `BLINK_LID_SHADE=0.10`，融进发影（旧版单一亮肤色 = "浅色胶带"）；
  ③ 接触线/重睑线画在真实接触点（框高 80%），部分眨眼不接触则永不画。
- 效果（4× 真机特写验证）：alt 全闭/半闭自然、眨眼首次可用；Q 版部分眨眼
  清晰可读（此前与全开无差别）；发丝零擦除、盖板与发影融合。
- 测试：全套 10 个测试文件通过（双运行时）。标定工作文件 `tools/_eye_calib.json`，
  评审图在 `docs/face_calib/`（网格/校验）与 `docs/face_frames/`（真机特写）。

### 8.10 鲸鱼玩偶色板回归（1× "灰团感"修复）
真机 1× 评审发现鲸鱼玩偶与立绘制服蓝糊在一起。采样确诊三个原因：
主体饱和度只有规范色板一半（通道差 32-48 vs 规范 ≥84）、描边跑成暖棕
（规范 #2A2028 深暖紫黑）、抠图边缘白色 halo。ImageGen 通路不可用
（无内建工具/无 KEY），改走 `tools/whale_retint.py` **像素级后处理**：
色相归位 + 饱和度 ×2.1、描边/眼/缝线归一 #2A2028、肚皮降温、
邻透明区浅色像素透明化去 halo（原素材备份 `_gen/cut_whale_v1_grey.png`）。
形体/姿势未变 → `pivot_y=1.0` / `ratio=0.56` 无需重标。真机 1× 验收：
玩偶明确可读，与制服蓝、小黑猫均能区分；全套 10 个测试文件通过。
详见 `配件美术规范.md` §8.4。

### 8.11 P0 解耦：摘掉「WorkBuddy 专用挂件」的帽子（2026-09-25）

原先有三处「产品定义级」硬耦合，不修则**装到别人机器上根本跑不起来**。已全部修复：

| # | 原问题 | 修法 |
|---|---|---|
| ① | `install.py` 预检没有 `~/.workbuddy/projects` 就 **`return 1` 中止安装** | 改为查**任一已注册数据源**；一个都没有也只**警告**不阻塞 |
| ② | 守望**只在 WorkBuddy 运行时才拉起桌宠** | `wb_whale_watcher.active_agents()` 复用登记册的**声明式探针**；主循环的「会话」语义从**进程实例**泛化为**活跃 agent 集合** |
| ③ | 联动关闭以 **WorkBuddy 退出**为信号 | `wb_whale_win._host_alive()`：宿主 = 活跃 agent 集合 |
| ④ | 3 个 dev 工具/测试硬编码技能绝对路径 | 改为项目内相对路径 |

**两个差点埋雷的细节**：
1. **活跃探测器原先只在「配件开启」时创建**，但它同时是联动关闭的判据 → 关掉配件会让联动关闭
   **悄悄退回只认 WorkBuddy**，解耦等于白做。现在 `__init__` 无条件启动它。
2. **三值语义必须保住**：`_host_alive()` 返回 `True/False/None`，`None` = 探测未知
   → 联动关闭什么都不做。否则启动瞬间的空集合会被误判成「全退出了」而**误关桌宠**。

## 10. 红线与经验（别踩）

### 设计红线（同原版，不得违背）
1. **古见几乎不说话**：不加台词，表达靠表情动效。
2. **动效数字只写在 `wb_motion.py`**（单一事实来源），业务代码只消费不定义。
3. **窗口保持 `WS_EX_NOACTIVATE`**，不抢焦点。
4. **数据不可读时保留上次值**，不闪零不崩溃。
5. **口径勿改**：轮次 = `conversationRequestId`；缓存命中 = `prompt_cache_hit_tokens`；
   用户提问 = `<user_query>` 标签内内容；日期归属 = 轮次首次调用的本地时区日期。
   改了会同时影响看板、桌宠、macOS 悬浮球三处。

### 工程红线
6. **探测/解压/网络一律放后台线程**，绝不进 Win32 消息循环
   （历史教训：把带超时的网络请求放进 timer tick → 消息循环每秒被卡死半秒、拖动不跟手）。
7. **新增 agent / 配件只改 JSON**，不要写 `if agent == "xxx"`。
8. **素材必须 `save_down()` 回逻辑尺寸**（忘了会落盘 6 倍大图）。
9. **打代码补丁前先归一化 CRLF → LF**：`wb_whale_win.py` 是 CRLF，
   多行锚点用 `\n` 会**全部失配**，且 `assert` 中断会导致补丁**根本不写入**
   （表现为"改了但没生效"）。
10. **补丁脚本里用 `chr(10)` 构造换行**——heredoc 里的 `\n` 可能被吞成 `/n`。
11. **ImageGen 的 `background="transparent"` 不可信**，必须自己验证 alpha 通道。
12. **换素材必须重标 `pivot_y` / `ratio`**（目视标定，无法自动推导）。
13. **写配置只写自己的登记册**。`wb_agent_registry.set_enabled()` 是本项目**唯一会写配置**的函数：
    白名单（只认已登记 key + 布尔值）+ 备份 + 原子替换。**绝不碰任何 agent 自己的配置文件**
    —— 那是 Clawd 的路线（往 20 种格式里写 hooks，100 个文件 / 3.7MB），我们不重复那个代价。
14. **L3 进程探测对 CLI 类 agent 基本无效**：Claude Code / Codex / Kimi 都寄生在
    `node.exe` / `python.exe` 上，靠进程名判「在跑」不可靠。能稳定识别的是**有独立 GUI 或独立服务**的
    （WorkBuddy / ZCode / DSH-web）。要给 CLI 类做「活跃状态」，最终仍得上 hooks。
15. **沙箱会在每次工具调用结束时回收后台进程** → 「起服务 + 验证」**必须在同一次调用内**完成，
    跨调用也不行（本轮为它白跑了两趟）。
16. **打补丁前先归一化 CRLF → LF**；多行锚点连续失配时改用「**按行号替换 + 替换前 assert 校验**」；
    补丁脚本里的换行一律用 `chr(10)` 构造；锚点里**别用 ASCII 双引号套双引号**（本轮因此失败三次）。

### 通用方法（可复用）
- **先看图再动手**：诊断美术问题必须看放大图 + 立绘裁图对比，先判断是"形状问题"还是"渲染语言问题"。
- **三层校验**：孤立图 / 语境图 / 真机图。
- **"同一份信息写两处"必漂移** → 让生成器产出契约、运行时读取。
- **沉默失败最贵**：截断、重复计数、状态写死这类"不报错但结果是错的"问题，
  必须靠**自洽性校验**（如 `cached ≤ prompt`）和**真机像素差分**来兜。
