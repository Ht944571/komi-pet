## 5. 关键决策与理由（别推翻它们，除非有更好的）

| 决策 | 理由 |
|---|---|
| **透明窗口用 `UpdateLayeredWindow(ULW_ALPHA)`** | **逐像素命中测试是系统白送的**——透明区点击自动穿透，不需要凸包近似、不需要轮询光标 |
| **2D 运行时零第三方依赖** | 只 import 标准库。**代价要知道**：运行时**不能**用 numpy / PIL 做位图分析 → 需要几何数据就在**构建期**算好写进 JSON（`content_box` 就是这么来的） |
| **动作 = 帧序列，不是运行时播视频** | 播放效果一帧不差（所有播放器内部都是逐帧位图），但运行时**不需要任何视频解码器**——零依赖红线保住，打包照旧 |
| **`wake`（醒来）不单独做素材，用 `doze` 倒放** | 观感正好是「从托腮变回端坐」，**首尾帧天然对齐**；省一半素材还比重新生成更准 |
| **`present`（举本子展示）复用 `write` 的后段** | 同一段视频里翻页之后的镜头，没必要拆两份 |
| **`HEAD_SCALE` 按头大小对齐两批素材** | 待机是近景、写字是全身，直接播切换时头会跳。**这是取景对齐，不是"变成同一个人"**——头身比本来就不同 |
| **动作音效统一归一化到 60% 峰值** | 原始峰值差 5.7 倍（拿本子 95% 刺耳 / 坐着 16.7% 听不见），不归一化三个状态响度完全不成比例 |
| **待机/困了/写字循环播音效** | 都是**持续状态**，播一遍就没声了。素材 4.1~4.5s 与循环动画几乎等长 |
| **菜单弹出期间冻结重绘** | `TrackPopupMenu` 是**模态**的、自己跑消息循环；定时器照跳会跟菜单抢 UI 线程 → 鼠标划过菜单项一顿一顿 |
| **`ANIM_MS` 必须 ≥ 素材帧率** | 改素材帧率时容易漏掉这里，两处脱节 = 白转（曾停在 66ms/15fps，每秒丢 9 帧） |
| **Agent 接入用声明式登记册** | 新增 agent **只改 JSON 不改代码** |
| **不碰 agent 自己的配置文件** | Clawd 那种"往 20 种格式写 hooks"要 100 文件 / 3.7MB，不复制那个代价 |
| **看板时间口径只有一个来源** | 后端 `_day_cond()` 是唯一实现；**任何地方都不要自己再解析一遍 days**（踩过：`_daily` 自解析导致 `yesterday` 直接 500） |
| **残留 working 会话：显示层停更过滤 + 启动自愈写库** | 2026-09-28 事故：宿主崩溃不落终态 → 气泡永远"运行中"。working 且停更 **15 分钟**（`wb_hover_core.WB_STALE_AFTER_SEC`）判残留不计活跃；写库只动复查后仍是 working 的行。这是"working=权威状态"的**唯一例外**，误判代价=气泡提前回落、下一笔事件自愈 |
| **看板接口的缓存 key 必须带参数** | `f"kpi:{days}:{agent}"`。只改签名不改 key → 切口径命中旧缓存，**数据看着不动且不报错** |
| ~~3D：程序化变换 + morph target~~ | 🗄️ 随 3D 线退役 |
| ~~立绘：按脸宽归一 + 交叉溶解~~ | 🗑️ 随形态收敛删除（只剩一种动作，无从切换） |

### ⚠️ 一条要纠正的历史结论
`桌宠美术优化方案.md` 与旧代码注释里写着「**GDI 的 AlphaBlend 没有全局 alpha**」，
并据此放弃了淡入淡出。**这条不准确**：`BLENDFUNCTION` 的第 3 字节就是
`SourceConstantAlpha`，项目原有的 `_ALPHABLEND_BF = 0x01FF0000` 本身就是 `SCA=255`。
2026-09-26 实测确认，`Surface.blit_a` 即基于此。

### 交互

### 改配置

| 文件 | 管什么 |
|---|---|
| `app/.whale_settings.json` | 大小 / 气泡 / **音效** / 画质 / 联动关闭 |
| `app/assets/_agents.json` | **Agent 登记册**（新增/启停 agent 只改这里） |
| `app/assets/anim/<动作>/_anim_meta.json` | 帧素材元数据（画布 / 内容框 / fps / 帧数）—— 由转帧工具生成，**别手改** |

### 换动作素材

```bash
cd app
python tools/video_to_pet_frames.py <视频> --name <动作名> --fps 24 \
       --crop-bottom <水印高度> --out-size 420 --scale 0.68
```

🔴 **转帧前必须先停桌宠**（三件事都要做对）：

1. **桌宠通过 GDI+ 持有 PNG 句柄** → 覆盖写会 `PermissionError: [Errno 13]`。
   先 `taskkill /PID <桌宠PID>`（不带 `/F`），守望会在几秒内用新代码拉起。
   转帧较慢时**把守望也停掉**（停守望要带 `/F`，不带会报"只能强行终止"）。
2. **`--fps 24`**：素材是 24fps，转帧别抽稀。改完还要确认 `wb_whale_win.ANIM_MS`
   （约为 41）**跟得上**，否则等于白转。
3. **转完核对 `_anim_meta.json` 的 `count`/`fps`**，别拿日志有没有报错当判据 ——
   删旧帧失败会让转帧**静默中断**，而前半段日志照样正常打印。

⚠️ **动作名必须与 `wb_anim.ACTIONS` 中的名字一致**（`idle/doze/sleepy/pickup/write`），
否则桌宠加载不到。

### 沙箱环境限制（会反复遇到）

- **`safe-delete` 在中文路径下必然失败**（把「古见同学桌宠」解成乱码）→
  删目录用 `cmd //c "rd /s /q <dir>"`、删文件用 `cmd //c "del /f /q <file>"`
- **区分两种报错**：`[safe-delete] … trash-failed` = 路径编码 bug；
  `另一个程序正在使用此文件` = **真的被占用**
- **HTTP 代理会拦 localhost**（测本地接口报 502）→ 用
  `urllib.request.build_opener(urllib.request.ProxyHandler({}))` 绕开
- **每个工具调用结束会回收后台进程** → 想长期运行只能靠自启机制，或在用户自己终端跑

## 8. G4（打包）现状

### ✅ Windows：已完成（2026-09-27）

**不走 Tauri，直接原生打包** —— 2D 运行时零第三方依赖、本来就是原生 Win32，
加一层 Web/游戏引擎是纯亏。Windows 用 PyInstaller 冻成 exe，用户**不用装 Python**。

- 出包：`<venv>/python.exe packaging/build_win.py` → `dist/古见同学桌宠-Windows-<版本>.zip`
  （**当前 76.4MB** —— 素材涨到 50MB，见下）
- 实测：`packaging/verify_win.py` → **17/17**
- 关键改造：`app/wb_runtime.py`（可写/只读分离 + `self_cmd` 自身唤起 + `free_console`）
- 完整说明：[`Windows打包-2026-09-27.md`](Windows打包-2026-09-27.md)

🔴 **打包体积增长的原因与取舍**：动作素材从 6.4MB 涨到 50MB（5 个动作 × 100+ 帧 @24fps），
zip 从 17MB → 76.4MB。这是「帧序列 + 24fps」的固有代价，换来的是零解码依赖与一帧不差的播放。
**如果以后要压体积**：降 `--out-size`（当前 420，实际显示约 254px）、或对 PNG 做量化。

**自更新已就位**：发布方给一个 `update.json` 清单，客户端 `--set-update-source` 指过去，
