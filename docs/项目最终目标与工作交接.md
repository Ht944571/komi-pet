## 1. 这个项目最终要做什么（North Star）

> **做一个可跨平台安装、开箱即用的桌面宠物；它站在桌面上，替你盯着各个 AI agent 的用量。**

拆成四句可执行的目标：

| # | 目标 | 现在的状态 |
|---|---|---|
| **G1** | **它是一个桌面宠物**：立在桌面最上层、透明、不打扰任何其他窗口 | ✅ 2D 单形态（v3 美术） |
| **G2** | **它展示各 agent 的用量**（轮次 / 调用 / Token / 模型 / 项目 / 会话 / 趋势） | ✅ 数据层与看板已完成 |

| **G4** | **跨平台可直装**：Windows / macOS / Linux 各一个安装包，双击即用 | ⏸️ 方案已定，**实现未开始** |

**当前的产品重心**：G1 的美术与动效**已按用户提供的参考视频重做到位**（2026-09-26）。
G2 / G3 已可用，**G4 是下一阶段**。

## 3. 产品线：**只有 2D 一条**（2026-09-26 起）

早期同时存在 2D 与 3D 两套桌宠、由守望按 `pet_mode` 切换。**3D 线已退役并移除**：

```
hover.py → wb_whale_win.py     （GDI+ 分层窗口，零第三方依赖）
```

**为什么退役**：
1. 用户决策——**审美线统一**到 v3 Q 版立绘，不再维护第二套审美
2. 3D 引入 moderngl / glfw / trimesh / pygltflib / Pillow 五个第三方依赖，2D 是**零依赖**的
3. 3D 的形态键眼睑是**平板**，在大图上能看出边缘（见归档里的已知问题）
4. 收益递减：3D 的自由环绕视角对"桌面摆件"这个用途不是刚需

**为什么 2D 能承接**：参考视频里姿态切换是**交叉溶解**而非动画；而交叉溶解、分层差分眨眼
这些"看起来像 3D 才有"的效果，在 2D 上用真实像素 + 全局 alpha 就能做到（见 §5）。

> 退役内容全部在 `docs/archive/`（方案文档 + 9 张截图），**运行时代码已删除**。
> `git rm` 前已确认：**没有任何运行时代码引用它们**（守望入口、托盘菜单、测试均已同步清理）。

## 5. 关键决策与理由（别推翻它们，除非有更好的）

| 决策 | 理由 |
|---|---|
| **透明窗口用 `UpdateLayeredWindow(ULW_ALPHA)`** | **逐像素命中测试是系统白送的**——透明区点击自动穿透，不需要凸包近似、不需要轮询光标 |
| **2D 运行时零第三方依赖** | 只 import 标准库。**代价要知道**：运行时**不能**用 numpy / PIL 做位图分析 → 需要几何数据就在**构建期**算好写进 JSON（`_build_meta.json` 的 `content_box` 就是这么来的） |
| **Agent 接入用声明式登记册** | 新增 agent **只改 JSON 不改代码** |
| **不碰 agent 自己的配置文件** | Clawd 那种"往 20 种格式写 hooks"要 100 文件 / 3.7MB，我们不复制那个代价 |
| **立绘：同源素材 + 按脸宽归一 + 统一画布** | 保证切表情**不跳尺寸**；"文件里一致 ≠ 屏幕上一致"，所以有 `verify_sprites_v3.py` 做真机回测 |
| **眨眼：分层差分（真实像素）而非椭圆盖板** | 眼位自动检测走不通（发/眼亮度分不开），所以拿"闭眼生成图与睁眼图的**差分区**"当眼睛——既不用标定，贴片 alpha 天然平滑 |
| **状态切换用交叉溶解** | 参考视频就是交叉溶解。实现前提是 `AlphaBlend` 的 `SourceConstantAlpha`——**"GDI 没有全局 alpha"的旧结论是错的**（见下） |
| ~~3D：程序化变换 + morph target，不用骨骼/关键帧~~ | 🗄️ 已随 3D 线退役（原理由：自由视角下预渲染帧只能覆盖固定角度） |
| ~~3D：底模重做优于后处理修补~~ | 🗄️ 同上（原实测：换底模提升远大于任何贴片处理） |

### ⚠️ 一条要纠正的历史结论
`桌宠美术优化方案.md` 与旧代码注释里写着「**GDI 的 AlphaBlend 没有全局 alpha**」，
并据此放弃了淡入淡出。**这条不准确**：`BLENDFUNCTION` 的第 3 字节就是
`SourceConstantAlpha`，项目原有的 `_ALPHABLEND_BF = 0x01FF0000` 本身就是 `SCA=255`。
2026-09-26 实测确认，`Surface.blit_a` 即基于此，状态切换的交叉溶解也用它。

## 6. 日常操作手册

### 跑起来

```bash
cd /d D:\workbuddy\古见同学桌宠\app
C:\Users\htft2\.workbuddy\binaries\python\versions\3.13.12\python.exe hover.py
```

### 交互

- **左键拖**=移动 · **右键**=菜单 · **左键点击身体**=按部位分档互动
  （**头→开心 / 脸→惊讶 / 胸腹→害羞~傲娇~石化分档 / 裙摆→委屈**）
- **双击泡泡**=开用量看板 · **长按**=憋气喷水
- **退出：右键托盘图标 → 退出古见同学**（窗口本身没有关闭按钮，也不接受键盘）

### 改配置

| 文件 | 管什么 |
|---|---|
| `app/.whale_settings.json` | 大小 / 立绘风格 / 气泡 / 音效 / 画质 / 配件（**当前配件已停用**）/ 联动关闭 |
| `app/assets/_agents.json` | **Agent 登记册**（新增/启停 agent 只改这里） |
| `app/assets/pet_v3/_eye_config.json` | 各态眼部/腮红锚点（由 `tools/remap_eye_config_v3.py` 生成，**别手改**） |

### 改美术 / 改布局（**必走这三步，顺序不能反**）

1. `python tools/build_pet_v3.py` —— 重建立绘
2. `python tools/remap_eye_config_v3.py` —— **重算眼部锚点**（缩放/贴图偏移变了就必须重算）
3. `python tools/verify_sprites_v3.py` —— **真机渲染核验**（脸宽极差 ≤5% 才算过）

换过美术或动过布局，**还要跑** `python tools/test_hit_regions.py`（点击分区与画面对齐）。

### 改完必跑回归

```bash
cd app/tools
for t in $(ls test_*.py); do py $t >/dev/null 2>&1 && echo "$t PASS" || echo "$t FAIL"; done
```
- ⚠️ **动态枚举，不要硬编码清单**——曾因此漏跑过新测试
- ⚠️ `test_scale_switch.py` 是**既有 flaky 用例**（详见 `美术v3重构交接-2026-09-26.md`
  最后一节：五个猜测已用实验排除，**别顺手改它**）

### ⚠️ 沙箱环境限制（会反复遇到）

**每个工具调用结束会回收后台进程**——`DETACHED_PROCESS` / `CREATE_NEW_PROCESS_GROUP` /
`cmd start` 三种都试过，全活不下来。
→ 想长期运行，只能靠**已有的自启机制**（守望已在 HKCU Run 里），或在用户自己的终端跑。

## 8. G4（打包）现状

### ✅ Windows：已完成（2026-09-27）

**不走 Tauri，直接原生打包** —— 理由是原假设对 Windows 不成立：2D 运行时**零第三方依赖**、
本来就是**原生 Win32**，加一层 Web/游戏引擎是纯亏。所以 Windows 用 PyInstaller 冻成 exe，
用户**不用装 Python**；macOS/Linux 是否仍走 Tauri/Godot 是另一件事。

- 出包：`<venv>/python.exe packaging/build_win.py` → `dist/古见同学桌宠-Windows-<版本>.zip`（46 MB）
- 实测：`packaging/verify_win.py` → **17/17**
- 关键改造：`app/wb_runtime.py`（可写/只读分离 + `self_cmd` 自身唤起 + `free_console`）
- 完整说明（含取舍与"改完怎么重打"）：[`Windows打包-2026-09-27.md`](Windows打包-2026-09-27.md)

**自更新也已就位**（§6）：发布方给一个 `update.json` 清单，客户端 `--set-update-source` 指过去，
之后启动会静默检查、有新版冒气泡提示、点右键「更新到 vX」才会下载替换（sha256 校验、数据不动）。
