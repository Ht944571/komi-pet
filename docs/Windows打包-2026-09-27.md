# Windows 打包（2026-09-27 落地）

> 结论先行：**Windows 版已可出包**，一条命令：
> ```bash
> <venv>/python.exe packaging/build_win.py     # 产物在 dist/
> ```
> 产物实测 **17/17 项通过**（`packaging/verify_win.py`）。

---

## 1. 为什么不是 Tauri / Godot

`目标任务-跨平台与多Agent接入.md` 里给 G4 定的方案是 Tauri v2 或 Godot，前提是
**「T4 表现层跨平台重写」** —— 因为当初的假设是"Windows 那套 Win32 代码没法跨平台"。

但那个前提**对 Windows 不成立**：

| 事实 | 影响 |
|---|---|
| 2D 运行时**零第三方依赖**（只有标准库 + 系统 gdiplus） | PyInstaller 能直接把整个应用冻成 exe，不需要用户装 Python |
| 2D 本来就是**原生 Win32**（不是 Web/游戏引擎） | Windows 上"用 Tauri 重写"是把原生换成浏览器内核，纯亏 |

所以：**Windows 只做原生打包**；macOS / Linux 是否仍走 Tauri/Godot，是另一件事，
不在本文范围。这样也把 G4 从"要重写三端"降成"先把最成熟的一端交付"。

## 2. 打包后必须解决的 3 个问题（难点都在这）

打包不是"压缩一下"。原代码有四处隐含假设，冻结成 exe 后**全会失效**：

### ① 可写数据原本放在"代码旁边"

原实现：`_HERE = dirname(__file__)`，设置 / 位置 / 数仓 / `wb_paths.json` 全在 app/ 下。
打包后 `_HERE` 指向**解包目录**（onedir 下是 `_internal/`），一旦装到
`Program Files` 这类只读位置，设置存不下、数仓建不起来。

**解法**：新增 `app/wb_runtime.py`，把「可写」与「只读」彻底分开：

| | 目录 | 谁 |
|---|---|---|
| 只读 | `bundle_dir()` = 包内 | `assets/`、`dashboard.html`、`chart.umd.min.js` |
| 可写 | `data_dir()` | 设置、位置、数仓、`wb_paths.json`、ccusage 缓存 |

`data_dir()` 优先级：
1. 环境变量 `KOMIPET_DATA_DIR`（测试 / 多实例隔离）
2. exe 同级有 `portable.txt` → `<exe 同级>\data`（**绿色便携版**）
3. `%LOCALAPPDATA%\KomiPet`

> **源码运行时 `data_dir()` 返回 app/** —— 与打包前**逐字节一致**，
> 所以既有的 1.2GB 本机数仓位置不变，17 个测试一条不用改（已实测）。

### ② "再拉起自己"的路全断了

桌宠 / 守望 / 看板 API 三者靠 `pythonw xxx.py` 互相唤起（守望拉起桌宠、
桌宠守护拉起 API、注册表自启指向 `pythonw`）。打包后**没有 pythonw、也没有 .py**。

**解法**：`wb_runtime.self_cmd(kind)` 统一出口 —— 源码 → `pythonw` + 脚本（逐字符不变）；
打包 → `[自身 exe, "--pet"|"--api"|"--watcher"]`。
入口 `hover.py` 加 `_frozen_dispatch()` 认这些子命令。

### ③ console 还是 windowed：两边都有坑，只能选一个并补上补丁

| | 好处 | 代价 |
|---|---|---|
| `--windowed` | 双击不闪黑窗 | **PyInstaller 会把 `sys.stdout` 置 None → 看板 API 的启动/自检日志整个丢掉**（这是我们唯一的排障线索） |
| `--console` | 日志、命令行输出全保留 | 双击会闪一下黑窗 |

**选了 `--console`**，然后消掉它的代价：
- 桌宠入口立刻 `RT.free_console()`（`ShowWindow(SW_HIDE)` + `FreeConsole()`）→ 看不到黑窗
- **登录自启走 `launch_hidden.vbs`**（`WScript.Shell.Run(..., 0)`）→ 一次都不闪
  （直接往 HKCU Run 写 exe 路径的话，每次登录都会闪，很脏）

### 附带修的：中文控制台乱码
中文 Windows 控制台默认代码页 936，而冻结程序按 UTF-8 写 stdout → 用户看到
`�ż�ͬѧ����`。`wb_setup.init_console()` 统一代码页与流编码到 UTF-8；
`安装.cmd` / `卸载.cmd` 再 `chcp 65001` 兜一层。

## 4. 构建与验证

```bash
# 一次性：把 PyInstaller 装进托管 venv
<managed python> -m venv <venv>
<venv>/python.exe -m pip install pyinstaller

# 打包（约 15 秒）
<venv>/python.exe packaging/build_win.py            # 加 --no-zip 只出目录

# 实测（必跑！）
<managed python> packaging/verify_win.py
```

`verify_win.py` **刻意只做安全验证**：绝不执行 `--install`/`--uninstall` ——
那会把开发者**真实**的 HKCU Run 自启项覆盖掉。自启命令行改由 `--check`
打印出来核对（`wb_setup.print_plan()`）。

验证项（17 条）：

| 组 | 验什么 |
|---|---|
| A | `--check` 退出码 0 / 认得出打包形态 / 立绘与看板页面都在包里 / 打印出自启命令行 |
| B | **包目录一个字节都没被写脏**（前后快照比对） |
| C | `--api` 起得来、`/api/health` 通、首页返回**打包进去的** dashboard.html、数仓落在数据目录 |
| D | `--pet` 真能起出 `WBWhalePetClass` 窗口、启动日志无异常、包目录仍干净 |

> ⚠️ D 组会**临时停掉正在跑的桌宠**（单实例互斥，不停就起不来第二个）。
> 守望进程会在几十秒内把源码版拉回来，`verify_win.py` 跑完也会把测试实例杀掉。

## 5. 改了这个项目之后要怎么重新出包

只要没动"可写/只读"的边界，就一条命令重打。**动了下面这些要格外小心**：

| 改动 | 需要同步 |
|---|---|
| 新增可写文件 | 路径必须走 `wb_runtime.data_dir()`，否则打包后写不进去 |
| 新增"再拉起一个进程" | 用 `wb_runtime.self_cmd()`，别写 `pythonw xxx.py` |
| 新增静态资源目录 | 加进 `build_win.py: stage_files()` 或 `--add-data` |
| 新增顶层模块 | PyInstaller 静态分析能找到 `import X`（含函数内的）；**动态 importlib 要加 `--hidden-import`** |
| 改素材目录结构 | 确认 `ASSET_SKIP_DIRS` 仍然正确（别把新素材误排除、也别把中间产物带进去） |

## 6. 自更新（发新版不用再让用户换包）

### 发版三步

```bash
# 1) 改 app/wb_version.py 里的 VERSION（唯一出处：打包脚本与运行时都读它）
# 2) 出包
<venv>/python.exe packaging/build_win.py
# 3) 生成清单（含 sha256）
<venv>/python.exe packaging/publish_win.py --notes "这次改了啥"
```

然后把 **两个文件**传到同一个位置（GitHub Release 资产 / 对象存储 / 内网共享 / 甚至本地目录）：

```
古见同学桌宠-Windows-1.1.0.zip
update.json
```

再让客户端指过去（**只需一次**）：

```bash
古见同学桌宠.exe --set-update-source <目录地址或 update.json 地址>
```

### 客户端行为

| 时机 | 行为 |
|---|---|
| 启动 / 每 24h | **仅在配了更新源时**静默检查；有新版 → 气泡提示一句 |
| 右键菜单 | 未配源**不显示**该项；配了 →「检查更新」；有新版 →「更新到 vX」 |
| 点「更新到 vX」 | 下载 → sha256 校验 → 解压 → 交给新版本替换 → 自动重启 |

### 设计要点（都有理由）

- **默认零联网**：没配更新源就一个请求都不发。这也是为什么菜单项在未配置时**不出现**——
  摆一个点了没反应的项比不摆更糟。
- **不用任何服务器**：清单就是普通 JSON，`http(s)` / UNC / 本地路径通吃；
  清单里的包地址支持**相对路径**（两个文件放一起即可）。
- **替换由"新版本的 exe"执行**：正在运行的 exe 与 `_internal/*.dll` 都被 Windows 锁着，
  当前进程改不了自己。流程是「解压到 `staged/` → 用 staged 里的新 exe 起
  `--apply-update` → 老进程退出」，于是**连替换逻辑用的都是新代码**。
- **失败绝不影响正在跑的桌宠**：任何一步出错都只是"这次没更新成"；
  设置与数仓**一个字节都不动**（这是打包时"可写数据挪出程序目录"的红利）。
- **必须能自证**：sha256 校验（清单没写 sha256 时会在日志里警告）+ 版本号逐段比较。

### 验证：`packaging/verify_update_win.py`（13/13）

在临时目录里模拟一台客户机，走完真实链路：

| 组 | 验什么 |
|---|---|
| 0 | 起点是旧版；设置更新源成功 |
| 1 | **sha256 不符必须拒绝**（负向用例），且版本不被改动 |
| 2 | `--check-update` 能报出新版 |
| 3 | `--update` 正常返回、写了更新日志 |
| 4 | **客户机真的变成新版**（这是最有说服力的一条） |
| 5 | 用户数据没被动、更新残留被清理、包内是新 exe |

> 收尾按**可执行文件名**结束进程 —— 开发机上你那只桌宠跑在 `pythonw.exe` 下，不会被误杀。

### 发新版时容易踩的（都踩过）

| 坑 | 症状 | 处理 |
|---|---|---|
| `launch_hidden.vbs` 用 UTF-8 存 | 更新/自启后桌宠**不回来**（路径里的中文乱掉，wscript 静默失败） | **必须 UTF-16（带 BOM）**写；`.cmd` 则用 UTF-8 + 首行 `chcp 65001` |
| 控制台没先设 UTF-8 | 输出满屏乱码；打印 ✅ 直接 `UnicodeEncodeError` 把命令打挂 | 入口先 `RT.init_console()` |
| staged 清理只做一次 | 残留删不掉（更新进程自己还占着文件） | 重试 ~12 秒，**删成功才移除标记** |

## 8. 代码签名现状（结论：现阶段不买）

### 影响面其实很小：**只有"从浏览器下载那一次"**

SmartScreen **只检查带 Mark-of-the-Web（来自网络标记）的文件**。实测本仓库构建产物
`MotW=False`，所以：

| 场景 | 弹警告吗 |
|---|---|
| 用户从浏览器下载 zip → 解压 | ⚠️ 会（解压会把标记带进子文件） |
| **程序自更新下载的包** | ✅ **不会** —— 更新器用 `urllib` 下载 + `zipfile` 解压，**不写网络标记** |
| U 盘 / 内网共享 / Steam 式客户端分发 | ✅ 不会 |

→ 这是一次性的首装摩擦；**更新路径天然免疫**。
（顺带：`--noupx` 已开，能降低被杀软启发式误报的概率；误报可免费向微软申诉。）

**不需要管理员权限**（装 `%LOCALAPPDATA%`），所以不会出现"UAC + 未知发布者"那种更烦人的弹窗。

### 真要签名，得知道这几条（2024 年后的现状）

| 事实 | 影响 |
|---|---|
| **EV 不再"秒过" SmartScreen**（微软 2024 年改了规则，OV/EV 同等对待） | 花了钱，**早期用户照样看到警告**，只是标题从"未知发布者"变成你的名字 |
| 信誉要靠**真实下载/安装量**积累 | 普遍要几周 + 几百次干净安装 |
| 私钥**必须放硬件**（USB 令牌或 CA 的云 HSM，2023 年起强制） | 多一层流程；CI 上签名要么插令牌，要么走云签名 API |
| 最便宜的 **Microsoft Artifact Signing（约 $10/月）只对美/加/欧/英开放** | 中国大陆开发者用不了 |
| 自签名证书 | **完全没用**（SmartScreen 只认 CA 链） |

可选路线（2026 年查到的行情）：SSL.com 个人版 ~$65/年 + 云签名订阅 ·
Sectigo/Comodo OV ~$219/年（含 USB 令牌）· DigiCert OV ~$400 / EV ~$685。

### 现在的替代做法（已落进包里）

1. README 里写清楚「更多信息 → 仍要运行」和「右键 zip → 属性 → 解除锁定」
2. 发布时**公开 sha256**（`update.json` 里就有），用户可 `certutil -hashfile` 自查
3. 明确告知：**自动更新不会再弹**（用户不会以为每次都要被拦）
