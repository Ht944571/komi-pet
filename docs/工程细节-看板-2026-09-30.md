# 用量看板 —— 口径 · 数据源 · 运维细节（2026-09-30 从 MEMORY.md 搬出）

> 代码：`app/wb_usage/dashboard.html`（前端）+ `wb_api.py`（接口）+ `wb_collect.py`/`wb_dw.py`（采集与数仓）
> + `agents/*.py`（各 agent 数据源）。硬规则精简版在 `MEMORY.md`；§3 的设计见 `工作交接-2026-09-28.md` §3/§14。

## 1. 时间口径：唯一实现在后端

- 🔴 **只有 `_day_cond()` 定义"某个 days 值是什么时间范围"**（today/yesterday/N/month/lastmonth/custom/all）。
- 🔴 `_daily` 里**只有纯数字**才走 `LIMIT` 优化，其余全靠 `WHERE` 过滤。
  曾两处分叉 → `days=yesterday` 抛 `ValueError` → 接口 502 → 前端 `Promise.all` reject →
  **整张看板静默停刷、页面一句报错都没有**（排查成本极高）。
- 🔴 前端 `loadAll` 里**每个请求各自 `safe()` 兜底**（`.catch` → null），单接口挂不拖垮全屏。
- 🔴 **接口缓存 key 必须带全部参数**（不带 `days`/`gran` → 切区间/切粒度时命中错缓存：数据不动且不报错）。

## 2. 口径与格式（容易被"看着不对"误解的几条）

- `hasCredit()` 对 `agent==='all'` 返回 **false** → 「全部」按 **Token** 统计
  （KPI 第一卡 =「Token / 轮次」均耗）；单选积分制 agent → 积分卡；非积分 agent → 计费方式卡。
- 🔴 **SQL `FILTER` 在 `WHERE` 之后生效** → `today_credit` 在非 today 口径恒 0。
  修法：今日值**单独再查**，且用**纯 agent 条件**（拿 `_conds()` 的 `rest` 拼会变成
  `day=today AND day='…'` → 空集）。
- **单日横轴按小时**：`/api/daily?gran=hour` → 24 桶（空桶补零、`cache_hit_rate` 留 NULL）；
  前端在"单日口径"（今天/昨天/自定义里的同一天）时带上 `gran=hour`，并在数据尾部补一个 null 空桶
  把横轴顶到 **24:00**（补 0 会看着像末尾暴跌），同时不画「日均」线。非单日仍按天（MM-DD）。
- 格式：`fmtCN()`（<1亿 取整「万」；≥1亿 一位小数「亿」）；卡前缀用 `rangeText()`
  （写 `'近'+range+'天'` 会拼出「近yesterday天」）。
- ⚠️ `api()` 内部**已经 `return j.data`**，别再写 `kpi.data`。

## 3. 数据源：新增一个 agent = 三步

采集器只认 `wb_usage/agents/` 下注册的 `AgentSource`：
① 写 `agents/xxx.py` ② 在 `agents/__init__.py` 的 `SOURCES` 注册 ③ `python wb_collect.py --agent xxx` 验证。
🔴 **改完必须重启看板 API**（它在自己进程里 import 源；不重启就还是老 `SOURCES`）。

| agent | 用量落在哪 | 形态 |
|---|---|---|
| workbuddy / codex / claude-code | jsonl 会话文件 | 文件源（按行游标） |
| **zcode** | `~/.zcode/cli/db/db.sqlite` 的 `model_usage` | **库型**（覆盖 `collect()`） |
| **opencode** | `~/.local/share/opencode/opencode.db` 的 `session_message`（assistant 消息 `data.tokens`） | **库型**；轮次按「最近一条用户提问」聚合 |
| **qwen-code** | `~/.qwen/{projects,tmp}/*/chats/*.json`（每条消息 `tokens`） | **整文件 JSON**（同走 `collect()`）；防御式解析，**认不出不出行** |
| kimi | ❌ 本机只有桌面版/webbridge，没有 CLI 会话日志 | 无可采集（装 CLI + 跑过一轮才能接） |
| ccusage | 本机缓存 JSON（需 Node） | 覆盖面补充源 |

实现要点：
- 库型/整文件源一律**只读**打开对方数据（`mode=ro`）——写会损坏对方（opencode/zcode 随时在写）。
- **幂等**靠 `(file_path, line_no)` 主键：`line_no` 必须由**源记录 id 派生稳定哈希**，
  递增序号每次重采都会错位产生重复行。
- ⚠️ `insert_rows(conn, path, src, rows)` 是 **4 参**（写测试夹具时最容易按文件源的 3 参写错）。
- **采集饿死**：`wb_collect.watch_changes` 原先只 stat **jsonl 文件**，库型源（ZCode/opencode）没有文件可盯
  → 会长时间采不到。现在靠 `BaseAgent.change_hint()`（源侧返回极轻量指纹，如 `MAX(rowid)`）
  + **60 轮保底强制采集**兜底。
- 采集报 `database is locked` = ODS 被 API 进程占着 → **重跑一次**即可（采集器 busy_timeout 5s）。
- 新增源的验证：`wb_collect.py --agent xxx` 采到行 → 接口 `/api/kpi?agent=xxx` 有数 → 看板 chip 有数。

## 4. 看板 API 的运维特性

- ⚠️ **API 进程没有消息循环** → `taskkill /PID`（不带 `/F`）会失败（「只能强行终止」）；
  改 `wb_api.py` 后要 `/F` 停，**api_guard**（桌宠内，60s 探一次、60s 冷却）会拉起新代码
  （实测 ~36s）。**永远不要只停不启**（它同时跑采集器和 30s 自检看门狗）。
- 看门狗（`_watchdog`）：自连 `/api/health`，超时 10s、连续 6 次失败才自杀
  （DB 忙时不计失败）；自杀前 flush 一行说明。自杀后靠桌宠的 api_guard 拉起。
- 看门狗里还有**兜底拉守望**（桌宠窗口 + 守望互斥体都不在 → 分离进程拉守望，10 分钟冷却）。
- 备份约定：`dashboard.html.bak_20260928_2123` 这类备份放**工作目录**；
  ⚠️ 临时文件**别放 `/tmp`**（沙箱调用间不可靠）。
- ⚠️ jsdom 竞态导致的 flaky 属既有问题（基线同样偶发失败）。
