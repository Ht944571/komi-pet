## 二·补、3D 线为什么退役（2026-09-26）

**不是失败，是审美线收敛。** 用户决定把精力与审美统一到 2D 的 v3 立绘集：

1. 参考视频里姿态切换**本来就是交叉溶解**，不是真动画 → 2D 用「真实像素 + 全局 alpha」
   就能做到（分层差分眨眼、状态交叉溶解），3D 的核心优势（自由环绕）不是刚需
2. 3D 引入 **5 个第三方依赖**（moderngl / glfw / trimesh / pygltflib / Pillow），
   而 2D 是**零依赖**
3. 3D 的眼睑是**平板 morph**，大图上能看出边缘（当时已记为已知问题）

**退役是怎么做的**（可照抄的清理流程）：
1. 先 `grep` 全仓引用面 —— 发现接线集中在 `wb_whale_watcher._pet_entry()`（自启入口）、
   `wb_tray.ID_MODE2D`（菜单项）、`test_pet3d_p0.py`
2. **先改代码再删文件**：守望入口固定为 2D、托盘移除模式菜单项、删掉对应测试
3. 编译 + 残留引用 grep 双重确认（只剩待删文件自身的自引用）
4. `git rm`（**文件都在 git 历史里，删除可完全恢复**，无需另外备份）
5. 文档与截图 **`git mv` 进本目录**（史料保留），修正所有指向它们的链接
6. 更新总纲 `项目最终目标与工作交接.md`

⚠️ 有一条历史结论**随 3D 一起被推翻**：旧文档说「GDI 的 AlphaBlend 没有全局 alpha」，
据此放弃了淡入淡出 —— 该结论不准确（`SourceConstantAlpha` 就在 `BLENDFUNCTION` 里），
2026-09-26 修正，并在 2D 上实现了交叉溶解。

## 三、还有价值、别当废纸的三处

1. **`④` 里的量化约束**：66ms 帧、粒子上限 24、三态立绘（idle/happy/pout）——
   这些是设计决策，后来固化成了 `wb_motion.py` 的令牌。改动画前值得回看当时的取舍理由。
2. **`⑥` 揭示的问题**：`_eye_config.json` 原先是「肉眼估算 + 三张立绘共用一套坐标」
   导致 pout 眯眼 / happy 歪头全对不上。现在的逐立绘标定就是这么来的。
3. **`①` 的上游协议是 MIT** —— 这也是当初敢于移植的许可前提，记录在案。
