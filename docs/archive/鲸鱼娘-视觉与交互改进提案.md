# 鲸鱼娘 · 视觉与交互改进提案

> 适用：拟人化鲸鱼吉祥物（空状态 / 加载 / 引导 / 成功 / 失败提示）
> 风格基线：日系萌系、圆润、低饱和高明度、蓝白主色
> 已结合当前桌宠实现（GDI+ 立绘 + 代码绘制装饰、动画帧 66ms≈15fps、粒子上限 24、三态立绘 idle/happy/pout）

---

## 0. 先定一条总原则

**她是一个"有呼吸感的静态角色"，不是一个"持续表演的动画角色"。**
90% 的时间她应该安静到几乎被忽略，只在被召唤（状态变化/用户交互）时才"活"一下。
萌系角色的可爱来自**比例与克制**，不是来自动作数量。

---

## 1. 待机动效（呼吸 / 尾鳍 / 眨眼 / 漂浮）

核心思路：**多条不同周期的正弦叠加**，避免同频同步（同步 = 机械感）。

| 动作 | 周期 | 幅度（scale=1.0 时） | 曲线 | 说明 |
|---|---|---|---|---|
| 呼吸起伏 | 3.2s（吸 1.4s / 呼 1.8s，非对称） | 上下 2.0px + 纵向缩放 1.015 | ease-in-out-sine，呼气段略缓 | 现在的实现是 `sin(t*2.1)*1.6`，建议改成非对称：用两段不同时长的缓动拼接，或 `sin` 加 0.15 相位偏移 |
| 尾鳍/下摆摆动 | 1.6s（与呼吸 1:2，故意错开） | ±7°，末端位移 3px | ease-in-out-sine | 若立绘是整张位图，可用"下半身裁剪后小幅旋转"或"整体 skewX 1.5°"近似 |
| 上下漂浮 | 6.0s | ±3px，叠加 ±0.6px 低频噪声 | 正弦 + 随机相位 | 幅度必须小于呼吸，否则像晕船 |
| 眨眼 | 每 4–7s 随机一次；15% 概率双眨 | 闭 100ms，睁 60ms | 闭 ease-out-quart / 睁 ease-out-back(1.4) | **性价比最高的一项**：只需一张闭眼立绘（或用代码在眼部画 2 个椭圆"眼睑"盖住），立刻从"贴图"变成"活物" |
| 眼神游移 | 每 8–12s | 瞳孔 ±1.5px | 200ms 移动 + 停留 | 让眼睛"看"不同方向，是生命感的关键 |
| 偶发吐泡 | 每 12–20s | 1–2 个小气泡 | 上浮 1.8s | 频率别高，高了变噪音 |

**节奏对齐提醒（本机 15fps）**：所有时长量化到 66ms 整数倍（100ms→132ms、200ms→198ms），否则在 15fps 下会出现"卡顿一帧"的错觉。

## 2. 情绪表情矩阵

统一一套"表情 = 眼部 + 嘴 + 姿态 + 配色 + 装饰"的五元组，每个状态只改必要的项。

| 状态 | 眼 | 嘴 | 姿态 | 配色 | 装饰 | 时长 |
|---|---|---|---|---|---|---|
| **成功** | 弯月眼（^ ^） | 小张口笑 | 身体上挺 4px、双鳍上举 | 主色 #5B8DEF → 强调绿 #4CD9A0，气泡描边同步 | 3 颗爱心 + 2 颗星，上浮 | 出场 500ms，保持 2.5s 后回落待机 |
| **失败/错误** | 下垂眼 + 眼下一道白高光（水汪汪） | 小 w 形（委屈不是生气） | 身体下沉 3px、鳍下垂 | **降饱和**：#8FA3BF，避免红色指责感 | 1 滴汗 or 一个下沉气泡 | 600ms 进入，保持，可重试时回待机 |
| **加载中** | 眼睛看向旋转方向 | 微张 | 极缓呼吸（幅度减半，避免与 loading 转圈抢注意力） | 常规蓝 | 3 个气泡依次弹出（间隔 160ms，循环 1.2s），或身旁一圈小漩涡 | 持续，≤3s 后加文字安慰 |
| **空数据** | 侧头 + 半睁 | 平 | 头部倾斜 8°、单鳍点腮 | 常规蓝，气泡用 50% 透明 | 气泡内一个"?"，1 个小气泡缓慢上浮 | 静态为主，呼吸照常 |
| **首次欢迎** | 闪亮眼（高光放大） | 大笑 | 从下方弹入：y+12→0，scale 0.85→1.05→1.0 | 常规蓝 + 一次整体提亮 | 4 颗爱心 + 问候气泡 | 入场 700ms，仅每会话 1 次 |
| **待机** | 常规 | 常规 | 呼吸 + 漂浮 | 常规蓝 | 无 | — |

要点：**失败状态不要用红色/怒容**。萌系吉祥物报错时应该是"她也很抱歉"，怒容会把情绪转嫁给用户。

## 3. 微交互反馈

| 交互 | 反应 | 时长 | 缓动 |
|---|---|---|---|
| **悬停** | 眼睛转向光标 + 身体 1.03 放大 + 气泡内出现小符号 | 进场 160ms / 退场 200ms | ease-out-cubic |
| **点击** | 压扁：scaleY 0.92 / scaleX 1.06（squash）→ 回弹过冲 1.02 → 归位 | 压 90ms，回弹 240ms | 回弹用 back-out(1.7) 或 spring(damping 0.55, stiffness 320) |
| **长按（>500ms）** | 憋气：身体鼓起 1.06、颜色略深、气泡出现"…"；松开瞬间"噗"喷 3 滴水花 + 回弹 | 蓄力 500ms，释放 260ms | 蓄力 ease-out-sine，释放 back-out(1.9) |
| **拖拽** | 身体朝运动方向倾斜（上限 8°）、眼睛看拖拽方向、拖拽越快倾斜越大（映射：8° × v/v_max） | 跟随实时，松手回正 200ms | 回正 back-out(1.5)；落地时一次 2px 下沉 + 小水花 |
| **状态切换** | 旧表情淡出 + 新表情弹入（不做位移） | 400–600ms | 淡出 ease-in-quart，弹入 back-out(1.4) |

**缓动速查**：
- 循环类（呼吸/漂浮）：`ease-in-out-sine` — 唯一推荐的循环曲线
- 出现/进入：`back-out(1.4~1.7)` 或 spring — 有"弹出来"的惊喜感
- 消失/退出：`ease-in-quart` 180ms — 干脆不拖沓
- **禁止 `linear`**（机械感源头）；禁止弹跳超过 2 次

## 4. 视觉细节（可爱感来源）

- **轮廓**：外描边 2px `#2E4A7D`（比填充深约 30%），**不要纯黑描边**（显脏）；内侧加 1px、12% 白的左上高光边，做出圆润的体积感
- **圆角**：所有几何元素圆角半径 ≥ 短边 25%；气泡尾部三个圆点由大到小（0.6 / 0.4 / 0.25 倍）指向角色
- **眼睛**：占脸宽 18–22%，眼距 = 1.2 倍眼宽（萌系黄金比）；每只眼两点高光（大 80% + 小 40%，对角放置）
- **腮红**：眼下偏外、椭圆、颜色 `#FF8FA8` 透明度 0.20（常态）/ 0.45（害羞）；**边缘必须羽化**，硬边会像贴纸
- **身体高光**：头顶偏左一条弧形高光，白色 12% 透明度，随呼吸一起轻微上下（幅度 1px）
- **水花**：3–5 滴，初速向上、重力 520px/s²，寿命 0.7–1.0s，尺寸 2.5–4.5px，落地即消失（不做二次弹跳）
- **气泡**：2–4 个，上浮 1.6–2.4s，尺寸 4–8px，横向 `sin` 摇曳，尾段放大 1.4 倍并淡出
- **投影**：椭圆软阴影，宽度 = 身体宽 0.72，随漂浮高度在 0.9–1.05 之间缩放（漂浮越高影子越小越淡）——这一条能立刻让"漂浮"可信

## 5. 克制原则（硬性上限）

1. **同时最多 1 个循环动效 + 1 个反馈动效**；反馈进行中暂停循环位移（只保留呼吸）
2. **位移幅度 ≤ 角色高度 4%**（200px 高 ≈ 8px），缩放上限 **1.06**
3. **循环周期 ≥ 2.5s**；快于此的循环一律视为噪音
4. **粒子并发 ≤ 12**（当前实现上限 24，建议下调），单朵粒子总时长 ≤ 2.4s
5. **单次反馈 ≤ 600ms**，同一状态重复触发节流 ≥ 1.5s
6. **空闲降频**：30s 无交互 → 关闭漂浮与自主行为，只保留呼吸 + 眨眼
7. **不遮挡**：气泡/粒子不得进入主内容区，保持 ≥8px 安全边距；**命中区用固定矩形**，不随动画位移（否则点击"打空"）
8. **输入/焦点态禁止位移**：用户在输入框打字时，角色只允许眨眼
9. **不做"情绪累积系统"**：不要因为点击次数多就永久改变性格表现（短期反应可以，长期状态机不要）

## 6. 降级方案

**三档动效强度**（建议直接做成右键菜单里的一项，和现有的"气泡/音效开关"并列）：

| 档位 | 表现 |
|---|---|
| 完整（默认） | 全部动效 |
| 精简 | 保留呼吸 + 眨眼 + 状态表情；关闭漂浮、粒子、自主行为；位移改为 120ms 透明度渐变 |
| 关闭 | 纯静态立绘；状态变化只切换表情帧，配 120ms 淡入淡出；无任何位移与粒子 |

**自动降级触发条件**：
- 系统 `prefers-reduced-motion: reduce` → 直接进"关闭"档
- 单帧绘制耗时 > 8ms（或帧率 < 30fps）持续 3 秒 → 降一档
- 笔记本电池供电 + 电量 < 20% → 降一档
- 当前实现跑在 66ms/帧（15fps），本身已相当于"精简档"的节奏，所以**位移类动效的时长必须按 15fps 量化**，否则会出现一帧跳变

**降级时的替代表达**：用"淡入淡出 + 表情帧切换 + 颜色变化"传达状态，不要简单粗暴地静止——静止 + 无反馈 = 用户以为卡了。

## 7. 优先级（投入产出比排序）

### 🥇 1. 眨眼 + 非对称呼吸曲线
- 成本：1 张闭眼立绘（或代码画眼睑）+ 改几行相位参数
- 收益：**从"贴图"变成"有生命的东西"**，是所有改动里感知提升最大、成本最低的一项

### 🥈 2. 眼神/身体朝向跟随光标 + 悬停微反馈
- 成本：光标坐标 → 瞳孔偏移映射（±1.5px）+ 身体 1.03 缩放
- 收益：**角色开始"看着你"**，交互意愿和好感度提升最明显；桌宠已有鼠标跟随的朝向逻辑，扩展到瞳孔即可

### 🥉 3. 情绪表情矩阵统一（成功/失败/空/加载四态）
- 成本：每个状态一组（眼/嘴/姿态/配色/装饰）参数表
- 收益：直接提升**信息传达效率**，空状态与错误提示不再只是"放个图"

**其余项排序**：4. 点击 squash 回弹（90ms+240ms）→ 5. 腮红/高光/软阴影细节 → 6. 水花气泡粒子调优 → 7. 拖拽倾斜 → 8. 长按憋气 → 9. 三档降级开关。

## 8. 应当避免的过度设计

- ❌ 全身骨骼 / 关节动画：成本指数级上升，15fps 下反而更僵硬
- ❌ 物理弹簧参数过大：过冲超过 2 次、持续抖动 = 廉价感
- ❌ 常驻粒子雨 / 泡泡机：任何时刻都在冒粒子的角色会让人烦躁
- ❌ 音效叠加到每次交互：音效只留给"确认"和"欢迎"，悬停绝不加音效
- ❌ 表情高频切换（<1.5s 一次）：变成表情包抽搐
- ❌ 全屏/遮挡式庆祝动效：成功提示不该打断用户下一步操作
- ❌ 多套配色主题（节日皮肤等）：先做一套打透，风格统一比花样重要
- ❌ 长期情绪 / 好感度系统：维护成本高、用户感知弱，属于典型的自嗨设计
- ❌ 用红色画失败表情：萌系角色发怒会把负面情绪转嫁给用户
- ❌ 命中区跟随动画位移：会让点击"打空"，是交互 bug 的常见来源
