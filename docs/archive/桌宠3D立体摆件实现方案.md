# 桌宠 3D 立体小摆件 · 实现方案（真 3D · 自由视角版）

> 文档性质：**实现方案**（造型/材质规范 + 技术架构 + 难点与可选方向）
> 输入：三视图参考图（前/侧/背）+ 10 秒渲染参考视频（1440×1440 / 30fps）
> 决策（2026-09-25 已定）：**头身比 1:1.6** ｜ **要自由视角旋转** ｜ **改成真 3D**
> 编写：小新 ｜ 关联：[`../桌宠美术优化方案.md`](../桌宠美术优化方案.md)（2D 线）｜[`../目标任务-跨平台与多Agent接入.md`](../目标任务-跨平台与多Agent接入.md)（T4）

## 0. 结论先行

| # | 结论 |
|---|---|
| 1 | 参考视频是 **NPR 平涂（cel）3D**，不是 PBR 写实摆件 —— **不是**高光/反射，唯一"3D 感"来自几何体积 + 柔和阴影斜坡 + 地面接触阴影 |
| 2 | **要自由视角旋转 ⇒ 必须实时真 3D** ⇒ 我原先推荐的「离线渲染 2.5D 帧序列」**出局** |
| 3 | 选型 **Godot 4**（不是 Tauri/three.js）。胜负手不是渲染，是**点击穿透**：Godot 内置多边形穿透；Tauri/Electron **完全没有** per-region hit-test |
| 4 | **最大的技术难点是「旋转中的点击穿透」** —— 剪影每帧在变，静态多边形对不上。解法见 §5.2（**凸包近似**，跨平台且无需 Win32 API） |
| 5 | **第二大难点是「眨眼」** —— AI 生成的模型没有骨骼/形态键，必须在 Blender 绑 **Blend Shape** |
| 6 | 数据层**零重写** —— 项目已有 8801 的 HTTP 接口与进程边界，Godot 直接调它 |

### 0.1 为什么"材质定性"依然重要

| 若参考是 PBR 写实摆件 | 实际是 NPR 平涂 |
|---|---|
| 有高光/反射/AO → 视角一变明暗就变 → 必须实时 3D | 平涂 → 换视角只换剪影 → **理论上预渲染够用** |

**但你要自由旋转，所以这条"规避优势"用不上了** —— 平涂只让**渲染管线更简单**
（不需要 PBR 材质/环境光/后处理），**不改变"必须实时"这个结论**。

> 实测依据：放大 900px 看发丝与面部 —— 头发平涂 2–3 层 + 粗线稿 + 一道淡紫高光带；
> 皮肤平涂暖白 + 刘海下柔边阴影；**无镜面高光、无反射、无次表面散射**。

## 1. 整体造型 · 材质 · 配色

### 1.1 造型比例（1:1.6，已定）

| 项 | 值 | 说明 |
|---|---|---|
| **头身比** | **1 : 1.6**（1.5 头身） | 盲盒/扭蛋比例，**唯一基准**（2D 立绘线同步改到此值） |
| 头高 : 全身 | 0.625 | 头占绝对主导 |
| 头宽 : 头高 | 0.88 | |
| 发幔 | **底端与脚齐平** | 长发幔两侧垂下，把身体框在中间 |
| 身体宽度 | ≈ 头宽 × 0.45 | 外套 + 百褶裙 + 短腿，被发幔夹住 |
| **剪影特征** | **上宽下窄的钟形** | 头顶 → 发幔外扩 → 收至脚部。**摆件最醒目的识别形** |
| **旋转友好性** | 360° 都成立 | 因为是**旋转体式剪影**（发幔环绕），**从任何角度都有形** —— 这点对自由视角至关重要 |

> 建模注意：1:1.6 的比例下**身体细节占比极小**（外套+裙仅约 0.28 个头高），
> 所以**面部与头发是全部重点**，制服细节**够看即可**，别在身体上过度建模。

### 1.2 材质方案（NPR，明确"不要什么"）

| 部件 | 材质 | 明确排除 |
|---|---|---|
| 全部 | **Toon / Cel 着色**，2–3 层平涂 + 粗线稿 | ❌ PBR ❌ 镜面高光 ❌ 环境反射 ❌ 次表面散射 ❌ 高光贴图 |
| 阴影 | **柔边阴影斜坡**（1 道软过渡） | 硬边 cel 会显得生硬 |
| 线稿 | **粗细分明的曲线描边** | 均匀描边像塑料玩具的模具缝 |
| 头发 | 平涂 + **一道淡紫高光带**（§1.3） | 不要各向异性 |
| **自由旋转下的形变要求** | 阴影**不随视角重算**（用固定的**前向光照**贴在模型上） | ⚠️ 否则转视角时明暗跟着变，**就丢掉了"平涂摆件"的质感** ——见 §7 难点③ |

> **关键设计决定**：为保住 NPR 的"平涂感"，**光照必须做成"贴在模型上的静态阴影"**
> （把阴影烘焙进贴图/顶点色），而不是实时光照。这样**转视角 = 只换剪影，明暗不变**，
> 与参考视频完全一致。这是 Godot 侧的具体做法：**Unshaded/toon 材质 + 烘焙好的明暗**。

> （否则转到侧面就断了）。这是 2D → 3D 转换最容易漏的一点。

## 2. 建模与动画

### 2.1 建模路径

| 路线 | 做法 | 质量 | 成本 | 建议 |
|---|---|---|---|---|
| **① AI 多视图 → 3D** | 三视图喂 `3d --multi-view`（front/left/right/back），出 GLB | 中（轮廓准、面部弱） | 低 | **起步用** |
| **② Blender 修形 + 绑骨 + 绑形态键** | 修面部/发丝 → 骨架 + 眼睑形态键 | **高（必需）** | 中高 | **必经**，见 §2.2 |
| ③ 完全手建 | 从零重新拓扑 | 最高 | 高 | 仅 ①②不达标时 |

⚠️ **本机无 Blender / Godot / Unity / 任何 3D 库**（已排查）。
**第一步必须先装 Godot 4 + Blender**（都免费）。

### 2.2 动画：**骨骼与形态键必须自己绑**

⚠️ **AI 3D 生成的是静态网格 + 贴图，不带骨骼、不带形态键。**

| 动作 | 实现 | 需要什么 |
|---|---|---|
| 待机呼吸 | 整体位移（不改形） | ❌ 程序化 |
| 待机摆动 | 整体旋转 ±2°（绕脚底轴） | ❌ 程序化 |
| **自由视角旋转** | **相机绕模型转**（不是转模型 —— 保住静态阴影的方向） | ❌ 程序化（Godot 里转 Camera3D） |
| 发梢飘动 | 发幔骨骼链 | ✅ 骨架 |
| **眨眼** | **眼睑 Blend Shape**：睁 / 半 / 闭 | ✅ **必须** |
| 表情（惊讶/开心） | 面部 Blend Shape，或贴图切换 | ✅ 需要 |
| 被点击反应 | 整体位移 + 缩放 + 表情 | 混合 |

**最小可用骨架**（够本方案所有动作）：
- 根骨（整体位移/旋转）
- 头骨（点头/歪头/朝向鼠标）
- **眼睑形态键 ×2（左右）3 态**：睁 / 半 / 闭
- 发幔 2–3 段（左右各一串，做飘动）
- 嘴：1 个形态键（"o" / 笑）

### 2.3 动作节奏（从视频实测）

```
待机（呼吸 2.2s + 轻摆 4s，相位错开 90°）
   ↓ 单击（2 帧渐入）
惊讶：睁大眼 + 张嘴"o" + 腮红加重，持 ≈1.0s
   ↓ 2 帧渐出 → 先眨 1 次回神
待机
   ↓ 双击（2 帧渐入）
开心：单眼 wink + 食指抵脸颊 + 大笑腮红，持 ≈1.4s（期间眨眼 1 次）
   ↓ 2 帧渐出
待机
```
**要点**：反应态**渐进 2 帧进 / 2 帧出**，**禁止瞬切**；回待机前**先眨 1 次**（"回神"感）。

## 3. 渲染与显示

### 3.1 选型对比（决策表）

| | **Godot 4** ⭐**选定** | three.js + Tauri | Electron + three.js | 原生 D3D |
|---|---|---|---|---|
| 3D + 骨骼 + 形态键 | ✅ 引擎原生 | ✅（glTF morph targets） | ✅ | 要自己写 |
| 透明窗口 | ✅ 文档化（见 §4） | ⚠️ macOS 有已知 issue | ✅ 成熟 | ✅ 最强（DComp） |
| **点击穿透（旋转剪影）** | ✅ **内置多边形穿透**，可每帧更新 | ❌ **无 per-region hit-test**，要 Rust 60fps 轮询 | ⚠️ `setIgnoreMouseEvents(forward)` 但**做不到随剪影变化** | ✅ 但要自己实现 |
| 体积 | +50~80 MB | +15 MB | +80~150 MB | 最小 |
| 跨平台导出 | ✅ 三平台 | ✅ | ✅ | ❌ 归零 |
| 上手成本 | 低（GDScript） | 中（需 Rust 侧） | 低 | 极高 |
| 与现有 Python 数据层 | **HTTP 直连现有 8801** | 同 | 同 | 同 |

**选定 Godot 4**。核心理由：**"旋转剪影的点击穿透"只有 Godot 有开箱方案**。
Tauri/Electron 在这一项上是硬伤（要自己轮询光标 + 读取渲染结果的 alpha，而 WebView 里读 canvas 像素很慢）。

### 3.2 Godot 渲染要点（保住 NPR 平涂感）

| 项 | 做法 |
|---|---|
| 渲染器 | **Compatibility**（社区实测透明更稳；Forward+ 在 4.4 有透明失效报告） |
| 驱动 | Windows 下设 **D3D12**，关闭"回滚至 Vulkan" |
| 材质 | **Unshaded** 或自定义 toon（明暗**烘焙进贴图/顶点色**，不依赖实时光） |
| 描边 | **反向外扩描边**（inverted hull，背面外扩 + 正面剔除） |
| 相机 | **转相机，不转模型** —— 保住烘焙阴影的相对方向 |
| 帧率 | **30 fps 上限**（摆件够用；空闲时降到 15 fps 甚至暂停） |
| 抗锯齿 | MSAA ×2（够；透明边缘用 pre-multiplied alpha 避免黑边） |

## 4. 桌面窗口透明与置顶

### 4.1 Godot 侧设置（已查证）

**Project Settings**（需打开 Advanced Settings）：
```
Display/Window/Borderless            = true
Display/Window/Transparent           = true
Display/Window/Per Pixel Transparency/Allowed = true
Rendering/Viewport/Transparent Background     = true
Display/Window/Subwindows/Embed Subwindows    = false   ← 关键，4.4 必关
```

**代码**（`_ready()`）：
```gdscript
get_viewport().transparent_bg = true
DisplayServer.window_set_flag(DisplayServer.WINDOW_FLAG_TRANSPARENT, true)
DisplayServer.window_set_flag(DisplayServer.WINDOW_FLAG_ALWAYS_ON_TOP, true)
DisplayServer.window_set_flag(DisplayServer.WINDOW_FLAG_BORDERLESS, true)
```

### 4.2 ⚠️ Windows 的一个特性（必须知道）

> **官方文档原话**：`window_set_mouse_passthrough` 的
> "**On Windows, the portion of a window that lies outside the region is not drawn**,
> while on Linux (X11) and macOS it is."

意思是：**Windows 上穿透区域外的部分根本不绘制**。社区里不少人以为这是 bug（"窗口被裁掉了"），
**实际上是特性，且对桌宠有利**：
- ✅ 省 GPU（透明区不渲染）
- ✅ 天然裁掉窗口外的内容
- ⚠️ 但**不能**把"窗口内不可见但需要显示"的东西画在区域外
- ⚠️ **跨平台行为不一致**：同一份代码在 macOS/Linux 上会绘制区域外内容 → 需按平台分别测试

### 4.3 置顶与压过全屏窗

现有项目已有成熟做法：**每 tick `SetWindowPos(HWND_TOPMOST)`** 压回顶层
（因为 WorkBuddy 自己有全屏 ATL 窗口会盖上来）。Godot 侧需要同样的
"定期重申 TOPMOST"，可用 GDExtension 或一个小型伴随进程（**复用现有 Python 守望进程**）。

## 5. 鼠标交互与触摸反馈

### 5.1 交互映射（含新增的"旋转"，需明确）

自由视角带来一个新问题：**拖拽到底是"移动摆件"还是"旋转视角"**？必须定死，否则用户困惑。

| 操作 | 行为 | 备注 |
|---|---|---|
| **左键拖** | **移动摆件**（贴桌面滑动） | 最高频操作，给最直觉的手势 |
| **右键拖** | **旋转视角**（水平 → Y 轴；垂直 → 俯仰，限制 ±25°） | 与"移动"分开，避免误触 |
| **滚轮** | **缩放**（0.7× ~ 1.5×） | 顺带把现有 `scale` 设置项接到这里 |
| 双击 | **摸头** → `joy`（wink + 指抵脸颊 + 爱心） | 现有行为 |
| 单击 / 戳 | **`surprise`**（睁大眼 + 张嘴"o"） | 新增 |
| 悬停 | **头部朝向鼠标**（头骨微转，±12°） | 3D 下比 2D 的"视线跟随"更自然 |
| 右键单击（不拖） | 打开现有右键菜单（配件/跟随/行为开关） | 保留 |
| 触摸 | Windows 触摸屏**默认模拟鼠标**，上述逻辑直接可用 | 多点手势低优先 |

> ⚠️ **"右键拖旋转"与"右键菜单"冲突**：判定标准是**位移阈值**（拖 > 6px 视为旋转，否则弹菜单）。
> 这是必须显式实现的细节，社区常见翻车点。

### 5.2 🔴 核心难点：旋转剪影的点击穿透（本方案的胜负手）

**问题**：Godot 的多边形穿透需要你给一个**静态多边形**；而自由旋转时**剪影每帧都在变**。
静态多边形要么太大（吃掉桌面点击）要么太小（自己点不到）。

**解法 A（推荐）：每帧用凸包近似剪影**
```
① 取模型在所有 Blend Shape 下的顶点集 → 预计算（离线）
② 每帧把当前相机矩阵作用到"包围点集"（可降采样到 60~120 个代表点）
③ 求投影后的 2D 凸包（Andrew monotone chain，O(n log n)，n≈100 极便宜）
④ 每帧调用 DisplayServer.window_set_mouse_passthrough(convex_hull)
```
- ✅ **跨平台**（纯 Godot API，不碰 Win32）
- ✅ **便宜**（120 点凸包 ≈ 微秒级）
- ✅ 对"内部没有洞"的摆件剪影**精度足够**
- ⚠️ 发幔与身体之间的**空隙点不到**（凸包会把它填上）—— 对摆件可接受，且**空隙本来就小**
- ⚠️ 需**限频**（每 3 帧更新一次即可，人在拖动时感觉不到）

**解法 B（Windows 专用，精度最高）：逐像素 alpha 判定**
- 用 Win32 `SetWindowLong(hWnd, GWL_EXSTYLE, WS_EX_LAYERED)` / `| WS_EX_TRANSPARENT` 切换
- 配合"光标下像素 alpha < 0.5 → 切穿透"
- ⚠️ 需要读回渲染结果的 alpha（Godot 里可用 `Viewport.get_texture().get_image()`，但**很慢，不能每帧**）
- ⚠️ 只有 Windows，跨平台要各写一套
- **仅作为解法 A 精度不够时的补充**

**本项目已有的优势**：现有 2D 版用的 `UpdateLayeredWindow(ULW_ALPHA)` **天生就有逐像素命中测试**
（alpha=0 处自动透传，零成本）。Godot **不走 ULW**，所以这项红利丢了 —— 这正是 §7 难点① 的实质。

### 5.3 点击反馈链（三层）

1. **动作**：整身后仰 2px + 缩放 96%→100%（2 帧）→ 进反应态
2. **表情**：`surprise` / `joy`（Blend Shape 动画）
3. **粒子**：`joy` 出爱心 3–4 颗（现有）；`surprise` 出 1 个「!」（新增）

## 6. 程序启动与常驻托盘

**全部复用现有实现**（这是本项目最贵的部分之一）：

| 能力 | 现状 | 3D 侧 |
|---|---|---|
| 开机自启 | HKCU Run（`KomiPetWhaleWatcher`/`KomiPetUsageApi`） | 新增第三项：Godot 桌宠 exe |
| 守护/自愈 | `wb_whale_watcher.py`：存活检测 + 崩溃重启 + 手动退出抑制 | **改为守护 Godot 进程**（逻辑不变，只换目标进程名） |
| 单实例 | 互斥体 | 复用 |
| **托盘** | 已有（右键菜单 + 持久化） | ⚠️ **Godot 无内置托盘** → **保留 Python 侧托盘**，两进程通过本地 socket/HTTP 通信 |
| 看板服务 | 8801 + 看门狗 | 不变 |
| 位置记忆 | `.hover_pos.json` | 迁移为 `.pet3d_settings.json`（含**视角角度 + 缩放**） |

> **架构决定**：**Python 继续负责托盘/自启/数据/守望，Godot 只负责渲染与交互**。
> 两者用**现有 8801 HTTP**（Godot 拉数据）+ **一个本地小 socket**（Python 发指令：退出/切配件/切 2D-3D）。
> 这个进程边界**现成**，不用新设计 —— 这也是选 Godot 而不是"把一切塞进引擎"的原因。

## 7. 关键技术难点（按严重度重排）

| # | 难点 | 严重度 | 应对 |
|---|---|---|---|
| ① | **旋转剪影的点击穿透** | 🔴 **高** | §5.2 解法 A（凸包近似，跨平台）+ 解法 B（Win32 逐像素，Windows 补充）。**这是全方案第一风险** |
| ② | **眨眼与表情** —— AI 模型无骨骼/形态键 | 🔴 **高** | 进 Blender 绑**眼睑 Blend Shape**（睁/半/闭）+ 嘴 1 个。**绕不过去** |

### 三、新架构（P2 已验证的形态）

```
┌─ 现有 Python 进程（不改）───────────────────────┐
│  数据层 / 看板 / 关注模式 / 配件逻辑 / 托盘       │
│  守望自启 / 位置记忆 / 交互语义                  │
└───────────────────────────────────────────────┘
                    ↕ 同进程内直接调用
┌─ 3D 表现层（新增，已验证）──────────────────────┐
│  glfw 隐藏窗建 GL 3.3 上下文                     │
│  moderngl 渲染到 FBO（RGBA + 深度）              │
│  glReadPixels → DIB（bottom-up，与 DIB 同向）    │
│  UpdateLayeredWindow(ULW_ALPHA) 贴上            │
│  → 透明 / 置顶 / 逐像素穿透 全部由窗口壳保证      │
└───────────────────────────────────────────────┘
```

**关键实现点**（都踩过并已解决）：
- GL 的 `glReadPixels` 是 **bottom-up**，DIB 用 `biHeight > 0` 也是 bottom-up → **直接拷贝，不用翻转**
- **DIB 只能创建一次**并选进 DC（曾写成"创建两次"，`bits` 与选入 DC 的位图不是同一块 → 贴出空白）
- ctypes：**必须逐个声明 argtypes/restype**，否则 64 位句柄按 c_int 截断
  （`OverflowError: int too long to convert`）；`WNDCLASSW` **不在 `ctypes.wintypes` 里**，要自己定义
- **透视矩阵第 3、4 行别写反**：写反后矩阵"看起来像"透视矩阵，但 `w` 变成 z 的函数 →
  顶点**全被裁掉、渲染全透明、GL 不报错**。验算方法：**`w` 必须等于 `-z_view`**

### 四、本次踩的 4 个坑（都在 `p3_real.py` 里注释了）

1. 🔴 **up 轴判错**：glTF 名义 Y-up，但 Hunyuan 导出的是 **Z-up**。
   直接用 Y 归一化 → **模型躺倒**。解法：**最大跨度轴 = 身高方向**（站立人形的启发式）。
2. 🔴 **Z-up 的旋转方向要试**：绕 X 轴 -90°（+Z→+Y）实测**上下颠倒**，
   说明该导出的"头"在 **-Z** → 改用 +90°（-Z→+Y）。
3. 🔴 **归一化位移的符号**：`(V-ctr)*scale` 后 y∈[-h/2,+h/2]，要让脚底在 0 必须 **加** h/2。
   写成减号会把模型推到原点下方 → **画面全空且不报错**。
4. **相机距离**：fov 30° / dist 2.3 只能看到 1.23 的高度，而模型高 1.62 → **装不下**。
   按 `2·dist·tan(fov/2) ≥ 高度×1.2` 算，应取 **dist ≈ 3.85**。

> 共同点：**四个坑都不报错，只是"画面不对"**。靠"打印归一化后的包围盒 + 出图看"逐个定位。

### 二、API 的三个实测限制（官方文档没写全）

1. **`Prompt` 与 `ImageBase64`/`ImageUrl` 不能同时存在** → 图生 3D 不能给文字提示。
2. **`MultiViewImages` 不能单独作为输入源**（报"Prompt、ImageBase64、ImageUrl 不能同时为空"）
   → 正确用法是 **主图 + 补充视图**。
3. **`ViewType` 只接受 `[back, left, right, top, bottom, left_front, right_front]` —— 没有 `front`**
   （主图即正面）。实测传 `front` 被拒。
   **`ViewImageBase64` 可用**（文档只写了 `ViewImageUrl`）——这是绕开"必须公网 URL"的关键。

> 成本：多视图 30 积分（Normal 20 + MultiView 10）。
> 另：**命令行长度**装不下三张图的 base64 → 本仓库的 `gen3d_direct.py` 改为
> **import 那个 skill 的模块、进程内直接调 API**，长度不受限。

### 三、绑骨 + 眨眼（`rig.py`）

**眼位是实测的，不是估的**：AI 3D 的贴图是混乱 UV 图集，无法按 UV 定位 → 用
`face_grid.py` **渲正脸 + 世界坐标网格**，人读标定（与项目 2D 版标眼部锚点同法）：

```
左眼中心 (-0.160, 1.020)    右眼中心 (+0.190, 1.020)
单眼 ≈ 0.200 × 0.140（y 0.95~1.09）
```

**眨眼的实现思路**（关键设计）：
v2 的脸已经够好，**再贴肤色片盖脸是倒退** → 改为**不碰原脸**，加两片
**肤色眼睑盖板**（上缘平、下缘弧的 D 形），眨眼 = 盖板**下滑**：
`blink_half` 下滑 0.150 / `blink_full` 下滑 0.300。
导出为 glTF **morph targets**（已验证 `lid_L`/`lid_R` 各 2 个 target）。

另加 `root` + `head` 两根骨（head 供后续做朝向/点头）。

### 四、本轮踩的坑

1. 🔴 **`np.eye(4, np.float32)` 第三次**（p2_verify / build_face / rig）——
   第二个位置参数是 `M` 不是 dtype。已**全局正则清扫**所有脚本。
2. 🔴 **纯色部件不能走明暗档**：盖板（无贴图网格）若也乘 cel 明暗档，
   会被压暗成**土黄**、与脸的浅肤色对不上 → **纯色部件必须走 unlit 路径**。
   （运行时同理，这条要带进正式实现）
3. 🔴 **睁开时盖板要藏进刘海**：初始位置只抬 0.128 会在额头露出两条盖板 →
   抬到 0.215 才藏住。
4. **别经 trimesh 取 `baseColorFactor`**：它转成 0–255 sRGB，再转回线性必然失真 →
   **直接从 GLB 读原始线性值**（pygltflib）。
5. **trimesh 不暴露 morph target** → 要 `pygltflib` 直接读 target 的 POSITION 增量。

### 三、动画实现方式及理由

**不用骨骼动画、不用关键帧序列，用「程序化变换 + morph target」**：

1. **呼吸/轻摆/走动颠簸** = 对整体做**正弦位移** —— 视频里这些动作本来就是
   周期性小幅度整体运动，程序化最直接，还能随意调频率/幅度
2. **眨眼** = **morph target（形态键）** —— 因为 AI 模型**没有眼睑几何**，
   无法用骨骼做出"眼皮盖下来"；改用"肤色盖板下滑"这个 morph，
   在平涂 NPR 风格里视觉效果等价，且只需 2 个 target
3. **惊讶/开心** = **状态机 + 程序化姿态**（后仰/小跳/歪头/眯眼）——
   视频里这两个表情的"脸"是靠贴图变化的，而我们的贴图不能改，
   所以用**整体姿态 + 眼睑开合**表达情绪（NPR 摆件的标准做法）
4. **不用关键帧序列**的原因：自由视角旋转下，**预渲染帧只能覆盖固定角度**，
   与"任意角度都要成立"矛盾；程序化变换天然与视角无关

### 四、视频里无法确认的细节 → 已用默认方案

| 细节 | 视频证据 | 采用的默认方案 | 关闭方式 |
|---|---|---|---|

| **随机走动** | 视频里**没有**走动（角色始终站着） | 幅度 ±160px、每 5–10s 一次、走一趟 2.2s | 设置 `wander:false` |
