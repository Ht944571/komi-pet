# 配件美术规范

> 本文档定义三个配件（小黑猫 / 复古小纽扣贝雷帽 / 鲸鱼玩偶）的**视觉语言**与
> **渲染管线**。改美术前先读它；新增配件照它做。

---

## 1. 为什么要有规范（第一版为什么不好看）

第一版配件是"用椭圆和三角拼出来的纯色剪影"，评审结论是**像剪贴画**。
对比立绘后确认根因不是形状，而是**渲染语言不一致**：

| 维度 | 立绘（目标风格） | 第一版配件（问题） |
|---|---|---|
| 描边 | 粗细分明的曲线线稿 | **无描边**（纯剪影） |
| 明暗 | 3 层以上硬边 cel | **单一平涂** |
| 体积 | 沿轮廓的亮边 | 无 |
| 配色 | 低饱和藕紫 / 制服蓝 | **高饱和亮蓝**（跳出色板） |
| 细节 | 每处形状有体积 | 贴纸式腮红、划痕式胡须 |

**结论**：先把渲染语言做成工具（`tools/artkit.py`），再重画形体。

## 2. 渲染规则（四条，与立绘对齐）

| # | 规则 | 数值 | 实现 |
|---|---|---|---|
| ① | **描边** | 宽 = 长边 × **2.0%**；线色 `#2A2028`（深暖紫黑，**不是纯黑**） | "描边压在填充下"：同形体先按线色描一遍，再盖填充 → 只露外轮廓，内部接缝被盖住。比 alpha 膨胀便宜且精确 |
| ② | **cel 明暗** | 光源固定**左上 45°**；暗部 = 形体 ∩ 自身右下偏移 k（k = 长边 × 4.5%），**硬边无渐变** | `overlap()` |
| ③ | **亮边 rim** | 形体 − 自身右下偏移 k = 左上内侧一条带 | `band()`。这是"有体积"的关键，立绘发丝上就有 |
| ④ | **接地影** | 柔椭圆，模糊半径 = 画布宽 × 3% | `contact_shadow()`。**站立物没有它会像悬空贴纸** |

抗锯齿：所有绘制在 **6× 超采样**画布上完成后 LANCZOS 缩回。

### 色板（取自立绘，改这里 = 改全部配件）

```
线色     #2A2028   深暖紫黑
藕紫系   #3C3648 / #282432 / #746C84    猫（"黑"用品红灰，纯黑会死板）
制服蓝   #4E5684 / #343A60 / #929CC8    贝雷帽
鲸鱼蓝   #566CC2 / #36448A / #8CA0E0    玩偶（玩具可比立绘鲜一点，但原版过亮像气球）
骨白     #FBF3EC                        纽扣 / 缝线
腮红     #EC98A8 低透明度                统一
```

## 3. 各配件的设计意图与关键决定

### 3.1 小黑猫（面朝右，58×46）

| 设计点 | 理由 |
|---|---|
| 头占比大（Q 版比例），身体小 | 可爱比例 |
| 尾巴 = **贝塞尔链**（一串半径递减的圆） | 自然并入轮廓；第一版是"一根断开的细线" |
| 身体色 `#3C3648` **比线色亮一档** | **第一版致命问题**：线色与填充都是深色 = 描边看不见。黑物体必须有明度差 |
| 眼睛 = **实心深色大眼 + 主/副高光 + 上眼睑线 + 外眼角上挑小勾** | "设计过的眼睛"与"白圆+黑点"的分水岭。第二版的白眼底+小瞳会**瞪眼** |
| **不要胡须** | 46px 下只有 1px，读作划痕 |
| 脚底接地影 + 前爪趾线 | 落地感 |

### 3.2 复古小纽扣贝雷帽（60×30，帽檐下沿 y=26）

> **本项目最大的一个坑，迭代 6 版才想明白：帽子的底边必须是平的。**

前五版都画成"完整的椭圆盘" → 底边的弧线露在外面 → 无论加多少褶/绒面/纽扣，
都只会在**盘子/飞碟**的框架里打转。真实贝雷帽戴在头上时底边被头发遮住，所以正确画法是：

```
上半个椭圆（拱顶，pieslice 180→360）  +  一条平的底边  +  底下一条更暗的汗带
```

轮廓是"**盖**"不是"**盘**"。

| 设计点 | 理由 |
|---|---|
| 底边平 + 拱顶（`Figure.pie`） | 见上。这是唯一能读作帽子的结构 |
| 三个拱顶椭圆叠出**不对称**（右下耷拉） | 对称 = 人造飞行器感；贝雷帽必然往一侧耷拉 |
| 绒面 = 3 条**短、低对比**弧，只在左上 | 第二版用长亮线横贯帽顶 → 读作**划痕**；第四版沿底边画整条弧 → 与内圈弧合成一张**笑脸** |
| **不要褶**（PLEATS） | 100px 下只会读作**栅栏** |
| 纽扣 = **骨白实心小圆 + 暗描边 + 高光**，位置偏心（36% 处） | 居中 + 任何圈状细节（红圈/两孔）= **一只眼睛**。复古感靠"形状 + 材质对比"，不靠红色 |
| 尺寸 ratio **0.94**（略小于实测头宽） | 1.12 超出 Q 版大头 → **军官帽**；0.70 太小 → **护士帽** |
| 下压 `dy_sprite = 0.135` | 帽子要"戴进去"，不是浮在发顶 |

### 3.3 鲸鱼玩偶（78×56）

| 设计点 | 理由 |
|---|---|
| 尾鳍 = **两串半径递减的圆**（与猫尾同法），短、圆、分开 | 第四版用"多边形+端点圆"→ 出来一根**带球的尖刺（像炸弹引线）**；第三版用两个独立椭圆 → **两个球** |
| 肚皮补丁**内缩** + 缝线环 | 外圈留本体色才读作"缝上去的布片"；第一版铺满 → **挖了个洞** |
| 侧鳍**贴体、向后掠、在轮廓内部** | 第三版画成体侧方块 → 读作**一条腿** |
| 背脊用**柔和暗边** | 第二版用虚线 → 读作**拉链** |
| **去掉喷水点** | 读作**烟囱** |
| 两眼同侧高光 | 不一致会像**斗鸡眼** |

## 4. 摆放契约（美术与定位的唯一真相）

**踩过的坑**：贝雷帽画布从 33 改到 30 后，`wb_accessories` 里硬编码的
`pivot_y = 27.5/33` 立刻失配——这是"同一份信息写两处"的典型。

**根治**：由生成器把**资产契约**写进 `assets/_acc_config.json`，运行时读取覆盖：

```json
"assets": {
  "beret":       {"pivot_y": 0.86667},
  "whale_plush": {"pivot_y": 1.0},
  "cat":         {"pivot_y": 1.0}
}
```

| 配件 | 尺寸基准 | 比例 | 锚点 | 说明 |
|---|---|---|---|---|
| beret | 实测头宽 | 0.94 | 发顶（`head_top`） | pivot = 帽檐下沿 |
| whale_plush | 实测头宽 | 0.56 | 胸口（底边对齐 `chest_y`） | 0.45 时存在感太弱 |
| cat | 立绘宽 | 0.34 | 地面（脚底贴地） | **不能用头宽**：Q 版头宽≈整幅宽，会把猫画得比她脑袋还大 |

**窗口净空**：`wb_motion.ACC_HEADROOM = 58`（scale=1 时）。Q 版头发顶到画面上沿，
帽身必须靠额外净空才能放下。分层窗口按 alpha 命中测试，多出的透明区不挡鼠标，功能零成本。

**越界兜底**：帽子 y 钳到 ≥ 0——极端缩放下宁可"戴低一点"，也不能被窗口裁掉半个帽顶。

## 5. 改美术的工作流（照这个顺序，别跳）

```bash
cd app/tools
# 1) 改 acc_art.py 的形体，然后只看孤立图（小尺寸 1x + 放大对照）
python -c "import acc_art as A; A.draw_beret().save('/tmp/x.png')"
# 2) **必须**合成到立绘上看（孤立看任何帽子都像盘子）
#    用 docs/art_ctx.png 那套脚本：紧裁 2x + 两种风格
# 3) 满意后落盘（同时刷新锚点表与资产契约）
python -c "import make_accessories as M; M.main()"
# 4) 真机出图（走 GDI 管线，验证落库路径）
python ../tools/shot_accessories.py
# 5) 回归
python ../tools/test_accessories.py
python ../tools/test_zstdio.py
```

三层校验缺一不可：**孤立图**看形体与细节、**语境图**看是否读得对、
**真机图**看 GDI 管线是否一致（像素差分为证）。

## 6. 诚实的边界

程序化绘图（PIL 图元）有**质量上限**：猫这种几何简单的形体可以做得很好，
但贝雷帽、布偶这类需要**织物质感与柔和过渡**的东西，达不到手绘/生成式插画的水准。

**当前状态**：
- 小黑猫 ✅ 定稿
- 贝雷帽 ⚠️ 读作帽子、比例正确，但仍是"程序化的干净感"，缺布料柔度
- 鲸鱼玩偶 ⚠️ 读作抱着的布偶，但表情与质感偏简单

**若还要提升**：这三个里**贝雷帽与玩偶是静态单图**，可以改用生成式出图
（透明背景）再接入，质量会有明显跃升；**猫不能**——它需要 14 帧一致的动画，
生成式无法保证帧间一致性，必须保留程序化绘制。

## 7. v7 定稿补充（2026-09-25）

### 又加的两个决定性识别特征

| 配件 | 新增 | 为什么 |
|---|---|---|
| 贝雷帽 | **帽檐外翻的唇边**（`fig.ellipse((1.5, 15.5, 54.5, 23.0))`） | 真贝雷帽的织物底缘会超出帽冠往外翻。**这是"软布帽"与"硬质帽"的分界**——没有它，轮廓再对也读作军帽 |
| 鲸鱼玩偶 | **背鳍** + **嘴线** | 这两个是鲸鱼最强的识别信号。少了它们，圆身子 + 尾鳍很容易读成"鱼"或"气球"。嘴线从吻端向后拉一条长而柔和的曲线，一条线就把"鱼"变成"鲸" |

### 尺寸比例必须按风格修正（一个建模错误）

实测 `head_w`（眼高行的不透明跨度）在两种风格下**量的不是同一个东西**：

| 风格 | head_w | 实际是 | 后果 |
|---|---|---|---|
| 高冷版 | 0.539 | ≈ 头骨宽 | 直接用没问题 |
| **Q 版** | **0.945** | **头发**（头骨约 0.56） | 按它算帽子 → 大得压住整个头 |

→ `KINDS["beret"]["ratio_by_style"] = {"q": 0.72, "alt": 0.94}`，
`compute_placement(..., style=...)` 优先取按风格修正的值。

### 另外两个踩过的工程坑（与美术无关但同样致命）

1. **忘了降采样 → 素材落盘 6 倍大**。artkit 在 6× 画布上作画，成品必须 `AK.save_down()` 缩回逻辑尺寸。
   忘了会落盘 348×276（逻辑 58×46），体积膨胀 36 倍，且只能靠 GDI 在绘制时缩——既耗性能又损画质。
   **表现是"看着还行但文件异常大"**，很容易漏。
2. **`wb_whale_win.py` 是 CRLF 换行**，多行锚点补丁用 `\n` 匹配会全部失配（且 `assert` 中断导致整个补丁不写入，
   表现为"改了但没生效"）。→ 打补丁前先 `s.replace("\r\n", "\n")` 归一化。

### 最终自评（诚实）

| 配件 | 评价 |
|---|---|
| 小黑猫 | ✅ **定稿**。几何简单，程序化绘制够好；描边/明暗/亮边齐全，与立绘同语言 |
| 贝雷帽 | ✅ **可用**。比例正确、读作帽子、有织物唇边；但仍是"程序化的干净感"，缺布料柔度 |
| 鲸鱼玩偶 | ✅ **可用**。读作抱着的海洋生物布偶，有背鳍/嘴线/缝线/肚皮补丁；表情与质感偏简单 |

**剩下的差距是程序化图元的固有上限**，不是调参能补的。若要再上一个台阶：
贝雷帽与玩偶是**静态单图**，可改用生成式出图（透明背景）显著提升；
**猫不能**——它需要 14 帧一致的动画，生成式保证不了帧间一致性，必须保留程序化绘制。

## 8. 生成式素材管线（2026-09-25 接入，贝雷帽 + 鲸鱼玩偶改用）

用户拍板「可以花费积分，只要效果好」后，贝雷帽与鲸鱼玩偶改用 **ImageGen 生成**，
质量对比程序化图元是**碾压级**的——毡呢质感、布偶的缝线与补丁、可爱的脸，都是图元拼不出来的。
**小黑猫必须保留程序化绘制**（14 帧一致的动画，生成式保证不了帧间一致性）。

### 8.1 流程

```
ImageGen（提示词里写死色值） → tools/gen_to_asset.py（抠棋盘格背景）
  → assets/_gen/cut_*.png → make_accessories.py 安装为 acc_*.png（+镜像 _f）
  → 重标 KINDS 的 pivot_y / ratio
```

提示词要点（**风格靠它统一**，否则三件素材会互相打架）：
直接把 artkit 令牌的**十六进制色值**写进提示词（body #566CC2 / shadow #36448A /
highlight #8CA0E0 / belly #E4EAF8 / outline #2A2028），并要求
「clean dark line art + hard-edged cel shading + two tones only」。

### 8.2 三个坑（第一个差点让整条路作废）

1. **`background="transparent"` 不被满足**。返回的是 **RGB 无 alpha**，
   而且把"透明"**画成了棋盘格图案**（浅灰/白交替的真实像素）。
   → 必须自己抠。判据见 `tools/gen_to_asset.py`：
   「中性且亮」（min(R,G,B) > 190 且 max-min ≤ 12）+ **从边界做连通传播**。
   连通传播不可省——物体内部的纯白高光（贝雷帽的骨白纽扣）会被颜色阈值误伤，
   只有"与边界连通"这一条能保住它。
   抠图实测：两张图各 ~1.3 秒，深底上零白边零棋盘残留。

2. **ImageGen 支持 `background` 参数但输出是 1024×1024 RGB**——分辨率与格式都要靠后处理，
   别指望工具帮你做好。

3. **换素材必须重标摆放参数**：生成式素材是 3/4 视角、自带倾斜与耷拉，
   `pivot_y`（0.62）与 `ratio_by_style`（q 0.82 / alt 0.90）都是**目视标定值**，
   无法从资产自动推导。换素材只换图不重标 → 位置和大小全错。

### 8.3 架构上的收尾

- **`make_accessories.py` 现在优先安装生成式素材**（`assets/_gen/cut_*.png`），
  **`acc_art` 退为兜底**——生成素材缺失时自动回退程序化绘制，不会开天窗。
- **每个 agent 一个数据源抽象、每个配件一个素材来源抽象**，都带兜底，
  这两条是本项目反复出现的模式。
- 程序化与生成式的**分工原则**：
  · 需要多帧动画一致 → 程序化（参数化形体，帧间天然一致）
  · 静态单图、需要质感与细节 → 生成式

### 8.4 生成素材的色板回归后处理（whale_retint.py，2026-09-25）

生成式出图会**漂移出规范色板**：鲸鱼玩偶首版主体饱和度只有规范的一半
（#90A0B0/#607090 灰蓝 vs 规范 #566CC2），描边跑成暖棕 #603010（规范 #2A2028），
抠图边缘留白色 halo——三者叠加，1× 下与立绘制服蓝糊在一起，"灰团感"。
修复走 `tools/whale_retint.py`（像素级后处理，不是重新出图）：

1. **主体蓝**：色相归位 225°、饱和度 ×2.1 加底、明度微压 → 回到 #566CC2 族
2. **暖棕描边/眼/缝线** → #2A2028 深暖紫黑（保留明度层次，与立绘线语言一致）
3. **肚皮暖奶油** → 向规范冷白 #E4EAF8 方向降温
4. **去 halo**：邻透明区（外扩 2px）内的浅色/粉浅像素透明化——不能用大核腐蚀
   （会把深色描边一起啃掉）；深色像素一律保留

原素材备份在 `assets/_gen/cut_whale_v1_grey.png`，处理就地写回 `cut_whale.png`
再跑 `make_accessories.py` 安装。真机验收：1× 下与制服蓝对比清晰、剪影干净。
**教训**：生成式接素材时，验收不能只看"形体对不对"，要拿色板采样核对
（`max-min` 通道差是饱和度的硬指标：规范族 ≥84，漂移版只有 32-48）。

## 9. 面部叠加层（眨眼盖板 / 腮红）与眼部锚点 v4（2026-09-25）

立绘之上的程序化面部元素（眨眼眼睑盖板、接触线、腮红）遵循同一套美术纪律，
锚点契约在 `assets/_eye_config.json`（v4），标定工具 `tools/calib_face.py`。

### 9.1 眼缝约定（v4 与 v3 的本质区别）

眼框 = **上睑缘→下睑缘之间的可见暗区**（含巩膜+虹膜，不含上方睫毛带/眉毛/发影）。
盖板行程全部发生在"看得见的眼睛"上：
- 旧 v3 框是"虹膜外扩的整眼"，顶部在睫毛带甚至刘海里 → 盖板行程一半消耗在
  头发上，**部分眨眼（40–70% 深度）几乎不可见**，全闭时还会把刘海发丝"擦掉"。
- 渲染侧配套参数（wb_motion.py）：`BLINK_LID_REST=0.28`（盖板从框顶 28% 处、
  即立绘自带睫线带的下缘"钻出"——自带深色睫线保持可见、充当闭眼的上睑）、
  `BLINK_LID_SHADE=0.10`（盖板色向眼线色收一档融进发影）。

### 9.2 lid_skin（盖板色）

每状态一个 `lid_skin` = 眼缝框下方皮肤带的实测均值色（`calib_face.py write`
自动采样）。眼周皮肤被刘海投影压暗、且腮红态带粉，**不要**用全局 skin_color
平涂盖板——"亮胶带"感就是这么来的。

### 9.3 标定工作流（锚点失配时照这个来）

```bash
cd app/tools
python calib_face.py grid alt_idle --crop 0.25,0.18,0.70,0.36 --zoom 4
```
