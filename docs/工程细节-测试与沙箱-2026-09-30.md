## 4. 沙箱与踩坑速查

| 现象 | 对策 |
|---|---|
| `[safe-delete] … trash-failed` | 中文路径下必然失败 → `cmd //c "rd /s /q <dir>"` / `del /f /q <file>` |
| `另一个程序正在使用此文件` | **真被占用**，与上一条是两回事 |
| 测 localhost 报 502 | 沙箱代理拦了 → `ProxyHandler({})` |
| 后台进程活不过一次工具调用 | 长期运行靠自启机制，或在用户终端跑 |
| PowerShell 工具不回显 stdout | 输出写文件再读 |
| 改大文件缩进算错仍过语法 | 方法被顶到 0 缩进 = 提前结束类 → 批量插入用脚本按锚点行 + `ast` 校验方法在目标类里 |
| `python - <<'PY'` 里塞含 `\n` 的补丁 | 会把 `\n` 弄坏 → 用 Write 写脚本文件再执行，或 Edit 逐处改 |
| 从 Bash 调 `cmd //c start …` | 沙箱会 SIGTERM（起常驻进程）→ 交给用户双击 .cmd |
| ctypes 传 HWND/HDC 报 OverflowError | 自己声明 `argtypes/restype`（`wt.RECT` 与模块自建 `RECT` **不是**同一个类型） |

## 5. 排查路径（按症状）

| 症状 | 先看 |
|---|---|
| 气泡/菜单「点了没反应」 | `%TEMP%/komi-wb-hover.events.log`（有无 `menu_*`/`act=` = 是否分发到）→ 再看 `.err.log` |
| 悬浮窗被压住 / 鼠标穿透 | ex-style 的 **TOPMOST(0x8)** 位；`WindowFromPoint` 在窗口内返回谁（不是自己 = 穿透）；`GetGUIThreadInfo(tid).hwndCapture`。三板斧在 `tools/_diag_menu_live.py` |
| **桌宠突然消失** | `%TEMP%/komi-watcher.log`（守望的判定/动作）→ 事件日志的 `host_gone`/`close_req`/`linked_close` → `.err.log`；三者都无 = 被外部强杀 |
| 桌宠不写字 / 一直在写字 | `tools/_diag_active.py`（逐会话给"活跃/排除 + 原因"）→ 再看采集链 |
| 桌宠不动了（画面冻结） | `_pet_fps.py`（像素哈希算帧率；24.4fps 正常，>1.5s 无变化 = 冻住）→ `_diag_write_tick.py`（tick/绘制耗时） |
| 看板数据不动 | `/api/health` 的 `last_collect`：冻结 + 源头库活跃 = 采集断；源头库活跃但 ODS 停 = 导入层；两头都停 = 上游 hook |
| 切换前台 agent 卡顿 | `tools/_prof_follow.py`（跟随链路逐段计时）→ 是否又直查了视图（应走 `turn_src()`） |
| 打开/选择菜单设置卡顿 | `tools/_prof_menu.py`（条目构建/建窗/重绘/悬停/子菜单/事后动作） |
| 桌宠窗口视觉验证 | `FindWindowW("WBWhalePetClass","WB Whale Pet")` + `PrintWindow(hwnd, memdc, 2)`（离屏渲染见 `tools/_shotutil.py`） |
| 进程/PID 与身份核实 | `tools/_diag_procs.py`（进程 + 启动时间 + 合成输入可用性）；**别拿 netstat 的 PID 直接强杀** |
