## ⚠️ 2026-09-26 自动拆层的实测结论（先读）

小新用「颜色分类 + 位置规则」做了**程序化自动拆层**，产出两个文件：
- `live2d/拆层_自动_v1.ora` —— Krita 底稿（合成重建能认出角色）
- `live2d/拆层_古见同学_v1.psd` —— **12 层分层 PSD**（Cubism Editor 可直接导入）

**诚实评估：以 Live2D 的标准只有 ~50%，不能直接用**。并排比对（`_work/psd_check.png`）显示：
| ✅ 对位的 | ❌ 缺失/错的 |
|---|---|
| 脸底、眼珠（完整圆）、腮红、外套、腿袜、后发垫底的位置 | **描边线稿整体丢失**（Live2D 没有描边就没有立体感） |
| 层的命名与绘制顺序 | 后发是**成色块**（背视发幔直接垫底，形状偏方） |
| | 前发残缺、裙条纹被并进头发色 |

**结论**：自动拆层的价值 = **帮你标出各部件的大致位置与层结构**，当参考用；
**真正的分层必须手工画**——尤其是描边（每层都要带自己的描边）。

**推荐工作流**：在 Krita 打开 `拆层_自动_v1.psd`（或 .ora 底稿）→ 把它当"部件位置参考"重画每层
（参考图就在文件里）→ 画完导出 PSD → Cubism 绑骨。
配合 `app/tools/make_psd_from_layers.py`：拆完后重跑一次可再生成干净的 PSD（规则在脚本里）。

## 0. 三条拆层原则（先读这个）

1. **你不是在画画，是在"切"**——形状和颜色都照参考图抄，只做一件事：把被遮挡的地方**补画**出来。
2. **每层都要"多画一圈"**——Live2D 会把图层做网格形变，边缘被拉扯时如果正好贴着另一层的边缘，就会露缝。**层与层的交界处要互相重叠 2~4px**（下层画大一点，上层盖住它）。
3. **宁可少拆，不要拆错**——必做层做完就能跑；可选层以后随时能加。第一次先只画 ★必做 的 13 层。

## 1. 图层清单（`拆层骨架.ora` 里已按此顺序建好）

从上到下 = Live2D 的绘制顺序（最前 → 最后）。**顺序错了会穿模**，别调换。

| # | 图层名 | 必做 | 画什么 | 要补画什么（关键！） |
|---|---|---|---|---|
| 01 | 发饰呆毛 | 可选 | 本设计无呆毛，可留空 | — |
| 02 | **前发** | ★ | 刘海 + **两侧垂到肩前的发束** | **被刘海盖住的额头**（一块肤色，边界照刘海内缘画）；侧发束与身体重叠处不用补（它在身体前面） |
| 03 | **眉** | ★ | 眉毛 | ⚠️ 本设计**眉与上眼睑是同一笔粗线**（见参考图眼睛上方那道深色粗条）——把"眼上的粗线"画在这一层，"眉尾"也画在这层。这样方案里"眨眼时眉毛下压"就只是这一层的动作 |
| 04 | **眼·上睑** | ★ | 上眼睑的**皮肤部分**（盖住眼球上半的那片肤色，含睑缘线以下的肤面） | 要比参考图里可见的范围**多画一截**——眨眼时它要往下盖到下睑 |
| 05 | **眼·瞳孔高光** | ★ | 深色眼珠 + 中间的浅色环 + 白色高光点 | **完整圆形**，别只画露出来的部分——眨眼/视线移动时它会转、会被眼睑盖住 |
| 06 | **眼·眼白** | ★ | 眼白（两眼各一片） | 比可见范围大一圈；本设计眼白只在下缘露一条，但形变时会露出更多 |
| 07 | **眼·下睑** | ★ | 下眼睑（下缘那条线 + 下方肤面） | 比可见的多画一点（眨眼时它会轻微上抬） |
| 08 | 鼻 | 可选 | 那个小点 | — |
| 09 | **嘴** | ★ | 嘴（本设计是一条短线） | **闭嘴与张嘴两套**：闭嘴照参考图画；张嘴画一个小的张口形状（深色+口腔色）。Live2D 用一个参数在两形之间插值 |
| 10 | **脸·肤色底** | ★ | 整张脸的肤色（含耳朵） | **整片脸都要有肤色**——眼睛/嘴/腮红都是贴在它上面的独立层，脸底必须完整不透明 |
| 11 | 腮红 | 可选 | 两团粉 | — |
| 12 | **身体制服** | ★ | 外套 + 衬衫 + 领结 | **被头发遮住的肩部/领口要补全**（后发层会盖住它，但它的形状必须完整，否则转头时露底） |
| 13 | 手臂左右 | 可选 | 本设计双臂垂放贴身，可以留在身体层里一起画 | 只有想做"挥手"才需要拆 |
| 14 | **裙摆** | ★ | 红条纹裙（从腰线以下整片） | **裙底与腿的交界要多画 3~4px**（物理摆动时裙摆会掀起） |
| 15 | **腿袜** | ★ | 黑色裤袜 + 鞋 | — |
| 16 | **后发** | ★ | **整个发幔**（含垂到身前的长发束、后脑的头发） | **这一层最容易画错**：正视图里的头发有相当一部分在**身体前面**（两侧长发束）——那些属于 02_前发；**只有"后脑 + 肩后"的部分属于这层**。形状参考 `reference/back.png`（背视图基本就是这一层的形状） |
| 17 | 补块·被遮挡区 | ★ | 一个"杂物抽屉"层（放最底）：被前发盖住的额头肤色、被后发盖住的肩部等 | 凡是上面各层没覆盖到的"露出时需要的底"，都丢进这层 |
| 90 | 参考·三视图 | 参考 | 已放好（32% 不透明度），锁定别动 | — |

## 3. 每一层"要补画什么"速查

| 被谁遮住 | 要补画的地方 | 怎么补 |
|---|---|---|
| 前发 | **额头**（一片肤色） | 从 `10_脸` 层复制肤色块，边界照刘海内缘 |
| 闭眼时 | **眼球下移后的位置** | `05_瞳孔` 画成**完整圆**，运行时靠参数让它上下移动（贝尔现象就是把这个圆往上移） |
| 后发 | **肩后被头发盖住的躯干** | `12_身体` 层把肩/领画完整（后发层盖住它） |
| 转头 | **侧脸轮廓** | 参考图 `side.png` 就是转头后的样子；2 头身的侧脸轮廓要画在 `10_脸` 与 `16_后发` 里 |
| 张嘴 | **口腔内部** | `09_嘴` 层里画张开的形状（深色 + 舌头色） |

## 4. Krita 操作要点

1. 打开 `live2d/拆层骨架.ora`——图层都建好了，**从下往上画**（先画 17_补块，再 16_后发……最后 02_前发），这样上面的层会自然盖住下面的。
2. **图层名不要改**（Cubism 导入 PSD 后按名字建 Part，名字乱会让绑骨变慢）。
3. 画完导出：**文件 → 导出 → PSD**（Krita 的 PSD 导出对图层/透明度支持足够 Cubism 用）。
   - 确认：背景**透明**、**没有合并图层**、图层名与 .ora 一致。
4. 画布 1024×1024 就够（桌宠显示才 200~300px，1024 是 3 倍余量）。想画 2048 也行，手册不用改。

## 5. Cubism 侧（你绑骨时的清单）

### 5.1 导入
Cubism Editor 免费版 → 导入 PSD → 每个图层自动成一个 ArtMesh。**按 .ora 的顺序排 Draw Order**（上=前）。

### 5.2 要建的参数（名字必须一字不差，运行时按名字驱动）

| 参数 | 用途 | 范围 |
|---|---|---|
| `ParamAngleX` / `Y` / `Z` | 头部左右转 / 上下点 / 倾斜 | -30~30 |
| `ParamBodyAngleX` / `Y` / `Z` | 身体摆动（视线/物理用） | -10~10 |
| `ParamEyeLOpen` / `ParamEyeROpen` | 左/右眼开合（1=睁 0=闭） | 0~1 |
| `ParamEyeSmile` | 眼睛笑弯（用于 happy） | 0~1 |
| `ParamEyeBallX` / `Y` | **瞳孔移动**（视线跟踪 / 贝尔现象） | -1~1 |
| `ParamBrowLY` / `ParamBrowRY` | 眉毛上下（眨眼时下压） | -1~1 |
| `ParamMouthOpenY` | 张嘴（0=闭 1=张） | 0~1 |
| `ParamHairFront` / `Side` / `Back` | 头发物理摆动（配物理文件） | -1~1 |
| `ParamSkirt` | 裙摆物理 | -1~1 |
| `ParamBreath` | 呼吸（也可由运行时驱动） | 0~1 |

### 5.3 必做的形变
- **眨眼**：`ParamEyeLOpen/ROpen` 0→1 时，`04_上睑` 往下盖到 `07_下睑`；`05_瞳孔` 在闭眼时**往上移**（贝尔现象）；`03_眉` 微微下压。
- **呼吸**：`12_身体` 上下 ±1~2px + `02_前发`/`16_后发` 跟着 ±0.5px。
- **物理**：给 `16_后发`、`14_裙摆` 挂摆锤（输入 = `ParamAngleZ` + `ParamBodyAngleX`），输出摆动。

### 5.4 导出（给运行时的清单）
```
model/古见同学.model3.json
model/古见同学.moc3
model/古见同学.physics3.json      ← 有物理就必须有
model/古见同学.userdata3.json     ← 没有可不导
model/纹理 atlas（Editor 自动出）
```
> ⚠️ **动作文件（motion3.json）不用导**——呼吸/眨眼/视线全部由运行时按参数实时驱动，
> 不走 moc 预烘焙动画（这是"桌宠要跟鼠标实时互动"决定的）。
